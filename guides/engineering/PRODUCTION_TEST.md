# Production Test Strategy

## 目标

本文整理通信接口量产测试策略，确保硬件焊接、接口连通性、基础协议和关键功能可在生产阶段验证。

## 通用原则

- 测试越早发现硬件问题越好。
- 优先测试连接和电平，再测试复杂协议。
- 每个外部接口至少有一个可自动化测试项。
- 测试结果应可记录、可追溯。
- 失败项要能定位到硬件、软件或外设。

## 测试层级

1. 上电和电源测试。
2. 引脚连通性测试。
3. 接口最小通信测试。
4. 目标设备 ID 读取。
5. 功能读写测试。
6. 压力和边界测试。
7. 结果记录和序列号绑定。

## UART

测试项：

- 回环测试。
- 固定字符串收发。
- 波特率配置验证。
- RS485 DE/RE 方向测试。

## I2C

测试项：

- 扫描目标地址。
- 读取 Chip ID。
- 写读可恢复寄存器。
- 总线恢复测试，视产品要求。

## SPI/QSPI

测试项：

- 读取 JEDEC ID。
- 小块读写擦除。
- QSPI 模式读取。
- XIP 基础校验，视产品要求。

## CAN/RS485

测试项：

- 与测试治具通信。
- 固定帧收发。
- 终端电阻检测。
- Modbus/CANopen 基础对象读取。

## USB

测试项：

- 枚举成功。
- VID/PID 正确。
- CDC/HID/MSC 功能测试。
- 插拔重连测试。

## Ethernet

测试项：

- PHY Link。
- 读取 PHY ID。
- Ping。
- TCP/UDP 回环。
- MAC 地址写入和唯一性检查。

## PCIe/SDIO/MIPI

测试项：

- PCIe 枚举和 Link Width/Speed。
- SDIO 设备枚举和固件加载。
- MIPI Sensor ID 或 Panel 初始化。
- 高速接口可通过功能性测试替代完整信号测试。

## 门限与判定示例

以下数值是示例，必须按产品规格、器件手册和客户要求调整。

| 测试项        | 示例门限             | 判定           |
| ------------- | -------------------- | -------------- |
| 电源电压      | 标称 ±5%             | 超限失败       |
| 静态电流      | 规格上限 + 10% 余量  | 超限失败       |
| UART 回环     | 1000 字节 0 误码     | 任一误码失败   |
| I2C 扫描      | 目标地址全部 ACK     | 缺一失败       |
| I2C 读写      | 连续 100 次无 NACK   | 任一失败复测   |
| SPI Flash ID  | 与 BOM 一致          | 不一致失败     |
| SPI 读写擦    | 全 pattern 比对一致  | 任一不一致失败 |
| CAN 收发      | 1000 帧 0 错误       | 任一错误失败   |
| CAN 终端      | 断电 60 Ω ±10%       | 超限失败       |
| RS485 方向    | 最后字节完整         | 丢字节失败     |
| USB 枚举      | 10 次插拔全部成功    | 任一失败复测   |
| Ethernet Link | 100/1000 Mbps 稳定   | 降速/断链失败  |
| Ping          | 1000 包 0 丢包       | 丢包超限失败   |
| PCIe Link     | 目标 Width/Speed     | 降宽/降速失败  |
| MIPI 初始化   | Sensor/Panel ID 正确 | 读不到失败     |

## 抽样与批次判定

| 场景              | 建议                      |
| ----------------- | ------------------------- |
| 关键安全/通信功能 | 100% 全检                 |
| 普通通信接口      | 100% 最小通信 + 首件全项  |
| 环境/寿命试验     | 每批次 3~5 台，按客户要求 |
| 新物料/新工艺     | 加严抽样 + 首件确认       |
| 连续失败          | 停线、隔离批次、失效分析  |

批次判定建议记录：

```text
批次号
抽样数量
失败数量
失败模式
是否允许返修/复测
放行/隔离结论
```

## 失败处理与复测

1. 记录失败项、原始日志、工位、治具和操作员。
2. 隔离失败品，避免混入良品。
3. 复测前确认失败可复现，避免“插拔后变好”掩盖问题。
4. 允许复测的项目要限制次数，并记录每次结果。
5. 连续失败触发停线和失效分析。
6. 返修品必须重新走完整测试流程。

## 夹具与测试点

- 测试点可达、防误触、避免结构件遮挡。
- GND 至少两个点，缩短回流。
- 高速信号测试点要控制 stub。
- 夹具探针压力、接触电阻和寿命要验证。
- 夹具 ID 与测试记录绑定。
- 测试治具本身要定期校准和点检。

## 门限与判定示例

以下数值是示例，必须按产品规格、器件手册和客户要求调整。

| 测试项        | 示例门限              | 判定            |
| ------------- | --------------------- | --------------- |
| 3.3 V 电源    | 3.20~3.40 V           | 超限失败        |
| 休眠电流      | ≤ 规格值 + 10%        | 超限失败        |
| UART 回环     | 10,000 字节 0 错误    | 任一错误失败    |
| I2C 扫描      | 目标地址全部 ACK      | 缺失失败        |
| I2C 读写      | 100 次 0 NACK         | 任一 NACK 失败  |
| SPI JEDEC ID  | 与 BOM 一致           | 不一致失败      |
| QSPI 读写     | 全地址 pattern 0 错误 | 任一错误失败    |
| CAN 终端      | 断电 55~65 Ω          | 超限失败        |
| CAN 收发      | 1,000 帧 0 错误       | 任一错误失败    |
| RS485 收发    | 1,000 帧 0 错误       | 任一错误失败    |

## 抽样与批次判定

| 场景              | 建议                          |
| ----------------- | ----------------------------- |
| 关键安全/通信功能 | 100% 全检                     |
| 连接器/焊接       | 100% 或高比例抽检             |
| 环境/寿命         | 每批次 3~5 台，按标准         |
| EMC               | 型式试验 + 变更后复测         |
| 长稳              | 每批次至少 1 台，持续 24~72 h |
| 新器件/新工艺     | 加严抽样并做首批验证          |

批次判定建议同时记录：

```text
一次通过率
复测通过率
失败分布（工位/器件/接口）
连续失败阈值
```

## 失败处理

1. 记录原始测量值和失败阶段。
2. 区分测试治具、DUT、线缆/连接器和操作问题。
3. 允许有限复测，但必须记录复测原因和次数。
4. 同一工位连续失败时暂停并检查治具。
5. 批次失败率超阈值时触发隔离、返修和根因分析。
6. 失败品维修后必须重新跑完整测试，而不是只跑失败项。

## 夹具与测试点

- 测试点可达、防误触、有丝印/坐标。
- GND 至少两个点，缩短回流。
- 探针压力、接触电阻和寿命满足量产节拍。
- 夹具线缆固定、屏蔽、长度可控。
- 夹具 ID、校准日期和维护记录可追溯。
- 测试程序版本与产品固件版本绑定。

## 测试记录

建议记录：

```text
产品序列号
硬件版本
固件版本
测试时间
测试工位
测试人员/治具 ID
每项测试结果
失败日志
测试治具 ID/校准状态
原始测量值（电压/电流/误码/丢包）
复测次数与结论
```

建议使用结构化记录：

```json
{
  "sn": "...",
  "hw": "...",
  "fw": "...",
  "fixture": "...",
  "station": "...",
  "timestamp": "...",
  "tests": [
    { "name": "uart_loopback", "result": "pass", "errors": 0 },
    { "name": "can_terminal", "result": "pass", "ohm": 60.2 }
  ],
  "retries": 0,
  "final": "pass"
}
```

## 结论

量产测试不应追求覆盖所有协议细节，而应覆盖：

```text
焊接正确
电平正确
接口可通信
关键外设存在
基础功能可用
```
