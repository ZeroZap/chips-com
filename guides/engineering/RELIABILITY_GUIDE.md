# Communication Reliability Guide

## 目标

本文整理通信可靠性设计方法，覆盖硬件防护、协议恢复、软件日志、长时间运行和现场维护。

## 硬件可靠性

关注：

- 电源裕量。
- IO 电平兼容。
- ESD 防护。
- 浪涌防护。
- 隔离。
- 终端匹配。
- 线缆和连接器可靠性。
- 地电位差。

工业现场优先考虑：

```text
RS485/CAN/Ethernet 隔离
TVS
共模电感
屏蔽线
可靠接地
```

## 协议可靠性

协议应包含：

- 超时。
- 重试。
- CRC 或校验。
- 序号。
- 状态机。
- 心跳。
- 离线检测。
- 恢复流程。

不要假设通信永远成功。

## 软件恢复策略

常见恢复动作：

```text
重新初始化接口
清空缓冲区
执行总线恢复
复位目标设备
重新枚举
降低速率
标记设备离线
```

恢复策略应避免无限快速重试。

## 错误统计

建议统计：

- 超时次数。
- CRC 错误。
- NACK。
- Bus Off。
- 枚举失败。
- 断线次数。
- 恢复次数。
- 最近一次错误原因。

这些统计对现场问题非常关键。

## 长时间运行

长时间测试关注：

- 内存泄漏。
- 计数器溢出。
- socket 资源释放。
- DMA 环形缓冲回绕。
- 日志刷写寿命。
- 温度漂移。
- 外设热插拔。

## 可靠性指标

| 指标     | 含义                 | 用途           |
| -------- | -------------------- | -------------- |
| MTBF     | 平均无故障时间       | 系统可靠性预估 |
| FIT      | 每十亿小时失效次数   | 器件级失效率   |
| 失效率 λ | 单位时间失效概率     | 串联系统计算   |
| 可用性   | MTBF / (MTBF + MTTR) | 维护和冗余设计 |
| 置信度   | 统计结论的可信程度   | 抽样与验证     |

串联系统近似：

```text
λ_total ≈ λ1 + λ2 + ... + λn
MTBF_total ≈ 1 / λ_total
```

这些指标用于设计取舍，不能替代现场数据和失效分析。

## 环境与寿命试验

| 试验          | 目的      | 关注点                   |
| ------------- | --------- | ------------------------ |
| 高低温工作    | 温度边界  | 时钟、PHY、Flash、连接器 |
| 温度循环      | 热胀冷缩  | 焊点、连接器、晶振       |
| 湿热          | 吸湿/腐蚀 | 绝缘、漏电、连接器       |
| 振动/冲击     | 机械应力  | 连接器、线缆、焊点       |
| 电源循环      | 上电冲击  | 复位、启动、Flash 完整性 |
| 电压跌落/暂降 | 电源异常  | 复位、通信恢复           |
| ESD/EFT/浪涌  | 瞬态抗扰  | TVS、隔离、地            |
| EMC 辐射/传导 | 电磁兼容  | 屏蔽、滤波、PCB          |

## 通信可靠性试验

| 试验     | 方法                  | 判定示例             |
| -------- | --------------------- | -------------------- |
| 长稳     | 24~72 h 连续收发      | 0 丢包/0 恢复失败    |
| 误码     | 已知 pattern 大数据量 | 误码率低于规格       |
| 断链恢复 | 拔插/断网/掉电        | 规定时间内恢复       |
| 故障注入 | 错误帧/CRC/超时       | 不崩溃、可恢复       |
| 边界参数 | 速率/温度/电压边界    | 不出现不可恢复错误   |
| 多节点   | 最大节点数/负载       | 延迟和错误率满足要求 |
| 热插拔   | 带电插拔              | 不损坏、可重新枚举   |

## 抽样与判定

以下为示例，按产品等级和客户要求调整：

| 项目       | 样本量          | 判定                   |
| ---------- | --------------- | ---------------------- |
| 高低温工作 | 3~5 台          | 全功能通过             |
| 温度循环   | 3~5 台          | 无焊点/连接器失效      |
| 长稳       | 每批 1~3 台     | 24~72 h 无不可恢复错误 |
| EMC        | 型式试验        | 满足适用标准           |
| 故障注入   | 每协议至少 1 台 | 可检测、可恢复         |
| 现场返回   | 全部            | 完成失效分析           |

判定要区分：

```text
功能性失效
性能降级
可恢复错误
不可恢复错误
安全隐患
```

## 失效分析

建议流程：

1. 保护现场，记录现象、环境、版本和日志。
2. 复现问题，缩小到硬件/软件/协议/环境。
3. 用 5Why、FMEA、故障树定位根因。
4. 制定修复和回归项。
5. 更新设计规范、测试用例和观测指标。
6. 跟踪现场返回，确认问题关闭。

## 降级策略

通信异常时可以考虑：

- 降低速率。
- 降低轮询频率。
- 禁用非关键数据。
- 保留安全控制通道。
- 切换备用链路。

## 现场维护

建议提供：

- 通信状态页面。
- 错误计数读取接口。
- 版本信息读取接口。
- 远程日志导出。
- 恢复或重启命令。
- 安全的固件升级机制。

## 结论

可靠通信系统不是没有错误，而是：

```text
能检测错误
能定位错误
能恢复错误
能记录错误
能避免错误扩大成系统失控
```
