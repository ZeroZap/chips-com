# nRF2401 / nRF24L01+（Nordic 2.4 GHz 私有收发协议）

## 定位

nRF2401 是 Nordic Semiconductor 在 2003 年推出的 2.4 GHz GFSK 单芯片射频收发器，工作在 **2.400 ~ 2.525 GHz** ISM（Industrial Scientific Medical，工业/科学/医疗）频段（125 个频道，1 MHz 步进），空中速率 **1 Mbps / 2 Mbps** 可选，发射功率 **0 / -6 / -12 / -18 dBm** 四档，接收灵敏度 **-82 dBm @ 2 Mbps / -85 dBm @ 1 Mbps**，典型空旷通信距离 **50~200 m**。

nRF2401 真正的市场主力是它的后代 **nRF24L01+（2008 年）**：把 ShockBurst 硬件链路层做到片上、加入 Enhanced ShockBurst 自动重传与 ACK payload、把寄存器接口化、降低功耗至峰值 < 14 mA 发射 / < 26 mA 接收。本文以 nRF24L01+ 为主、nRF2401 为辅统称为 **nRF2401 系**。

芯片形态：

| 型号 | 推出 | 主要变化 |
| --- | --- | --- |
| nRF2401 | 2003 | 第一代，DDS+PLL 频率合成，144 字节 payload，纯硬件位流接口 |
| nRF2401A | 2005 | 兼容 2401，简化引脚 |
| **nRF24L01** | 2006 | ShockBurst 链路层片上化，SPI 命令寄存器接口 |
| **nRF24L01+** | 2008 | Enhanced ShockBurst（自动重传 + ACK payload + 6 pipe），功耗降一半 |
| nRF24LE1 | 2011 | nRF24L01+ 收发器 + 增强 8051 内核的 SoC（已停产） |
| nRF24L01+ (PA+LNA) | 2013 | 加片外 PA + LNA 的 PCB 天线 / SMA 模块，2 Mbps 下空旷 800~1100 m |

nRF2401 系**不属于任何开放标准协议栈**（不是 BLE / ZigBee / Thread / Matter），它是 Nordic 私有的"轻量级硬件链路 + 应用层留给用户的半成品"。市面上大量"无线串口模块"其实就是 nRF24L01+ 跑 SI24R1 / XL2400 这类国产兼容芯片，SPI 接口、寄存器兼容、ShockBurst 协议兼容。

**核心定位差异**：nRF2401 是"硬件把 ShockBurst 帮你做了，链路层细节你不用管，但应用层完全靠你自己写"。所以它适合**对成本敏感、对应用层完全可控、对加密/认证没强制要求**的场景：无线鼠标键盘、遥控玩具、四轴飞行器遥控、简易板间串口替代、低成本传感器节点。

## 跟蓝牙 / Wi-Fi 的关键差异

- **nRF2401 没有 BLE 协议栈**：没有 GATT / ATT / L2CAP / GAP / SMP，没有 Service / Characteristic 抽象，没有连接参数协商，没有广播 payload 概念。所以"nRF2401 收数据"在主机端就是**从 SPI 读字节流**，没有回调事件系统。
- **nRF2401 没有认证 / 配对**：地址 = 5 字节硬编码（写入 `RX_ADDR_P0..P5`），地址匹配上就收。任何知道地址的人都能收到，所以**保密性 = 0**，要保密只能在应用层加加密。
- **nRF2401 不是无线串口**：市面上"无线串口模块"是在 nRF24L01+ 上跑了一层透传协议（SI24R1 厂商固件、PCB 模块厂商固件），主机侧才是 UART / USB CDC。nRF2401 本身只到 SPI byte 级别。

## 关键概念

### ShockBurst 与 Enhanced ShockBurst

nRF2401（2003）的 ShockBurst 是"硬件帮你拼包头 + CRC + 地址匹配 + 自动重发"，主机只管 `TX_PAYLOAD` 寄存器写入。nRF24L01+ 的 Enhanced ShockBurst 在此基础上加了：

- **6 个独立 RX pipe（P0~P5）**：每个 pipe 一个 5 字节地址、一个 payload 宽度、一个 enable bit。P0 还支持 3 字节 ~ 5 字节可变地址长度（其余 pipe 必须 5 字节）。
- **Auto-Retransmit (ART)**：`SETUP_RETR` 寄存器设重传次数（0~15）和重传延迟（250~4000 µs）。发射失败自动重发，直到 ACK 收到或超过次数。
- **ACK payload**：接收端在 ACK 包里"顺手"塞 1~32 字节给发送端，等于"双向数据"但共用一个 TX 周期。nRF24L01+ P0~P5 都可以发 ACK payload。
- **动态 payload length**：`FEATURE` 寄存器 `EN_DPL` 置位，payload 长度写在 `RX_PW_PX..` 但**实际长度**会按收到包的第一个字节自动截短（命令字后跟 LEN + 数据）。

### 频道（RF Channel）

`RF_CH` 寄存器 0~125，对应 2.400~2.525 GHz 频率 = 2400 + RF_CH（MHz）。125 个频道是 nRF2401 系的"跳频"基础，可以**手动跳频避让** Wi-Fi / 微波炉等同频干扰。

Wi-Fi / 蓝牙占用 2.4 GHz 的**前 13 个频道**（2.412~2.472 GHz，22 MHz 带宽），nRF2401 推荐避开 RF_CH = 12~74（2.412~2.474），用 75~125（2.475~2.525）。

### 数据速率与功率

`RF_SETUP` 寄存器：

- `RF_DR`：0 = 1 Mbps，1 = 2 Mbps
- `RF_PWR`：00 = -18 dBm，01 = -12 dBm，10 = -6 dBm，11 = 0 dBm
- `LNA_HCURR`：1 = 高电流 LNA（消耗 1 mA 多但接收灵敏度稍好）

### 地址管道（Pipe）与寻址

nRF24L01+ 有 6 个 RX pipe，每个 pipe 一个地址：

- **P0**：5 字节（默认）或 3~5 字节可变长（需 `EN_AA.P5` + 解锁）
- **P1~P5**：固定 5 字节

发送端 `TX_ADDR` 是发出去的"接收方地址"，与对方 pipe 地址匹配才会被收。P0 默认是 `TX_ADDR` 默认值（`0xE7E7E7E7E7`），上电默认匹配。

**最多 6 个一对一节点 + 1 广播**（如果广播地址用 P0，且所有节点都把 RX_ADDR_P0 设为广播地址）。

### ACK payload 双向通信

nRF24L01+ 的杀手级特性：

```text
时刻 0    A 发送 TX payload 给 B
时刻 1    B 收到，触发 RX_DR 中断
时刻 2    B 硬件自动回 ACK 包，里面塞 B→A 的 payload（如果 B 的 TX FIFO 有数据）
时刻 3    A 收到 ACK，触发 TX_DS 中断，并从 RX FIFO 读到 B 的 payload
时刻 4    一次"半双工"双向通信完成
```

一次"半双工"来回在 130~200 µs @ 1 Mbps / 80~130 µs @ 2 Mbps。这就是 nRF24L01+ "看起来像全双工"的根源。

### 自动重发（ART）

`SETUP_RETR`：

- `ARC`（Auto Retransmit Count）：0~15，0 = 不重发，15 = 重发 15 次
- `ARD`（Auto Retransmit Delay）：0~15，单位 250 µs，0 = 250 µs，15 = 4000 µs

如果 ARC 次内 ACK 没收到，触发 `MAX_RT` 中断，发射端把 TX FIFO 内容清空。

### CRC

硬件自动加 CRC：1 字节或 2 字节，由 `CONFIG.EN_CRC` 和 `CONFIG.CRCO` 控制。

## 硬件连接

### 典型应用电路

```text
MCU (SPI Master)                  nRF24L01+
─────────────                     ──────────
SCK  ────────────────────────►    SCK
MOSI ────────────────────────►    MOSI
MISO ◄────────────────────     MISO
CSN  ────────────────────────►    CSN  (低电平有效)
CE   ────────────────────────►    CE   (TX/RX 使能)
IRQ  ◄─────────────────────     IRQ  (低电平有效，开漏输出，需 MCU 上拉)
VCC  ── 3.3V                   VCC  (3.3V，**严禁 5V**)
GND  ────────────               GND
                                   ANT ── PCB 天线 / SMA / 弹簧天线
```

### 电源

**nRF24L01+ 严格 3.3V，电源不稳是 80% 失败的原因**：

- 峰值发射电流 14 mA @ 0 dBm（13.5 mA 短突发）、115 mA @ +20 dBm（PA+LNA 模块）
- **MSP430 / STM32 / nRF52 的 3.3V LDO 通常带不动**，需要单独 LDO（如 AMS1117-3.3 / LP2985）
- VCC 引脚 **100 nF + 10 µF 钽电容** 必须紧贴芯片
- PCB 天线模块的 VCC 与模块 GND 之间必须 10 µF 钽 + 100 nF 瓷片并联
- 如果是 5V MCU（如 Arduino UNO），必须用 **3.3V LDO + AMS1117-3.3** 降压，**不能直接接 VCC**

### 模块引脚

淘宝 / LCSC 上的 nRF24L01+ 模块（10 引脚 2.54 mm 间距）：

```text
  1  GND
  2  VCC (3.3V)
  3  CE   (TX/RX enable)
  4  CSN  (SPI chip select, active low)
  5  SCK  (SPI clock)
  6  MOSI (SPI master out, slave in)
  7  MISO (SPI master in, slave out)
  8  IRQ  (interrupt, active low)
  9  (NC)
 10  (NC) 或 GND
```

### PCB 天线 vs SMA 模块 vs Chip 天线

| 模块类型 | 距离（开旷 1 Mbps） | 体积 | 成本 | 适用场景 |
| --- | --- | --- | --- | --- |
| PCB 走线天线 | 50~100 m | 16×30 mm | 1~2 RMB | 玩具 / 鼠标键盘 |
| Chip 天线 | 30~60 m | 9×9 mm | 2~3 RMB | 紧凑产品 |
| SMA 棒状天线 | 200~500 m | 25×35 mm + 50 mm 天线 | 3~5 RMB | 长距离 / 调试 |
| PA+LNA + SMA | 800~1100 m | 25×40 mm + 50 mm 天线 | 4~8 RMB | 远距离 IoT / 遥控 |

### PCB 天线走线规则

- 天线走线 50 Ω，**禁止铺铜、过孔、走线穿过天线区域**
- 天线正下方的 PCB 层必须**挖空**（至少 5 mm 净空）
- 天线末端圆滑，避免直角
- 不要在电池、金属件附近

### CE 与 CSN 时序

```text
CE = 1 ─┬──────────────► TX 或 RX 启动
        │
        └─ CE 至少保持高 10 µs 才启动 TX
CSN     ┌──┐  ┌──┐  ┌──┐
        │  └──┘  └──┘  └──► SPI 命令窗口（CSN 低期间）
```

CE 高时启动一次 TX（如果 TX FIFO 非空）或进入 RX 监听（如果 `CONFIG.PRIM_RX = 1`）。CSN 是 SPI 片选，CE 是收发模式开关，**两者不能合并**。

## SPI 命令集与寄存器

### SPI 配置

- 时钟：0~8 MHz（nRF24L01+ 上限 10 MHz，实际 4~8 MHz 稳定）
- MSB 先发
- CPOL = 0, CPHA = 0（Mode 0）
- 最大单次传输：CSN 拉低后发 1 字节命令字，后跟 0~N 字节数据，再拉高 CSN

### 命令字

| 命令 | HEX | 方向 | 用途 |
| --- | --- | --- | --- |
| `R_REGISTER` | 0x00 | 读 | 读寄存器（后跟寄存器地址 + N 字节） |
| `W_REGISTER` | 0x20 | 写 | 写寄存器（后跟寄存器地址 + N 字节） |
| `R_RX_PAYLOAD` | 0x61 | 读 | 从 RX FIFO 读出收到的 payload（CSN 拉低后只发 0x61 就开始读） |
| `W_TX_PAYLOAD` | 0xA0 | 写 | 写入 TX FIFO（普通 ACK 模式） |
| `W_ACK_PAYLOAD` | 0xA8 + pipe | 写 | 写入 pipe 的 ACK 槽（0xA8~0xAD = P0~P5） |
| `FLUSH_TX` | 0xE1 | 命令 | 清空 TX FIFO |
| `FLUSH_RX` | 0xE2 | 命令 | 清空 RX FIFO |
| `REUSE_TX_PL` | 0xE3 | 命令 | 重发上一包（仅在 `CONFIG.REUSE_TX_PL` 已置位时） |
| `ACTIVATE` | 0x50 | 命令 | 激活 / 失活 R_RX_PL_WID / W_ACK_PAYLOAD / FEATURE 等高级功能（前置 0x73 激活，0xEC 失活） |
| `R_RX_PL_WID` | 0x60 | 读 | 读收到的 payload 实际宽度（动态 payload 模式） |
| `NOP` | 0xFF | 命令 | 读 STATUS 寄存器（CSN 拉低后发 0xFF 同时收到 status） |

### 关键寄存器

| 寄存器 | 地址 | 字节 | 关键位 | 说明 |
| --- | --- | --- | --- | --- |
| CONFIG | 0x00 | 1 | `MASK_RX_DR`/`MASK_TX_DS`/`MASK_MAX_RT`/`EN_CRC`/`CRCO`/`PWR_UP`/`PRIM_RX` | 主配置：中断屏蔽、CRC、上电、TX/RX 模式 |
| EN_AA | 0x01 | 1 | `ENAA_P0..P5` | 各 pipe 自动应答开关 |
| EN_RXADDR | 0x02 | 1 | `ERX_P0..P5` | 各 pipe RX 使能 |
| SETUP_AW | 0x03 | 1 | `AW` (01/10/11 = 3/4/5 字节地址) | P0 地址长度（其他 pipe 必须 5 字节） |
| SETUP_RETR | 0x04 | 1 | `ARC`/`ARD` | 自动重发次数 / 延迟 |
| RF_CH | 0x05 | 1 | `RF_CH[6:0]` | 频道 0~125（2400 + RF_CH MHz） |
| RF_SETUP | 0x06 | 1 | `LNA_HCURR`/`RF_DR`/`RF_PWR` | 速率、功率、LNA |
| STATUS | 0x07 | 1 | `RX_DR`/`TX_DS`/`MAX_RT`/`RX_P_NO`/`TX_FULL` | 状态（写 1 清中断） |
| OBSERVE_TX | 0x08 | 1 | `PLOS_CNT`/`ARC_CNT` | 丢包计数 / 当前重发次数 |
| RPD | 0x09 | 1 | `RPD` | 接收功率检测（已连接载波信号强度） |
| RX_ADDR_P0 | 0x0A | 5 | - | P0 RX 地址（与 TX_ADDR 默认值相同） |
| RX_ADDR_P1 | 0x0B | 5 | - | P1 RX 地址（典型用 5 字节地址） |
| RX_ADDR_P2..P5 | 0x0C..0x0F | 1 | - | P2~P5 地址（LSB 4 bit 可变，MSB 与 P1 共享） |
| TX_ADDR | 0x10 | 5 | - | TX 默认地址（默认 `0xE7E7E7E7E7`） |
| RX_PW_P0..P5 | 0x11..0x16 | 1 | `PW` | 各 pipe RX payload 字节数（0~32） |
| FIFO_STATUS | 0x17 | 1 | `TX_REUSE`/`TX_FULL`/`TX_EMPTY`/`RX_FULL`/`RX_EMPTY` | FIFO 状态 |
| DYNPD | 0x1C | 1 | `DPL_P0..P5` | 各 pipe 动态 payload 开关 |
| FEATURE | 0x1D | 1 | `EN_DPL_MDA`/`EN_DPL_PB6`/`EN_DPL` | 动态 payload / ACK payload 开关 |

### 写寄存器时序

```text
CSN ───┐                                          ┌───
       └────────┐                          ┌──────┘
                │  0x20  0x07  0x7E       │
                │  cmd    addr  value      │
       SPI:     │  ◄─────►◄─────►◄─────►  │
                │                          │
                ▲ CSN 拉低开始              ▲ CSN 拉高结束
```

### 读 STATUS 寄存器的标准做法

```text
CSN ───┐                ┌───
       └────────────────┘
         0xFF   ──►  status 0x0E  (RX_DR=1, TX_P_NO=2)
```

每次 SPI 传输的首字节同时是命令字 + 上次的 STATUS（与命令字解耦），所以拉低 CSN 后读一个 0xFF 就拿到 STATUS。

## 通信流程

### 上电时序

```text
VCC 稳定 ──► 拉低 CE ──► 等待 100 ms 起步振 ──► SPI 配置寄存器 ──► PWR_UP=1 ──► 等待 1.5 ms 启动振荡器 ──► 设置 PRIM_RX 进入 RX，或 CE=1 启动 TX
```

nRF24L01+ 上电后默认 PWR_UP=0，需要先写 CONFIG.PWR_UP=1，等待 1.5 ms 振荡器稳定后才能进入正常收发。

### TX 流程（发送端）

```text
1. PWR_UP=1, PRIM_RX=0
2. 写 CONFIG（屏蔽 TX_DS 中断）
3. 写 TX_ADDR（5 字节，接收方 P0 地址）
4. 写 RX_ADDR_P0（接收方 P0 地址，用于 ACK 匹配）
5. 写 EN_AA.ENAA_P0 = 1（开自动应答）
6. 写 SETUP_RETR（ARC=10, ARD=2 → 500 µs 重试 10 次）
7. 写 RF_CH（频道 2.400 + RF_CH MHz）
8. 写 RF_SETUP（速率 + 功率）
9. W_TX_PAYLOAD 写入 payload（1~32 字节）
10. CE 拉高 ≥ 10 µs，启动 TX
11. 等待 IRQ：
    - TX_DS = 1 → 成功，清中断
    - MAX_RT = 1 → 重发超限，清中断 + FLUSH_TX
    - 4 → 4010 µs 超时还没回
```

### RX 流程（接收端）

```text
1. PWR_UP=1, PRIM_RX=1
2. 写 CONFIG（屏蔽 RX_DR 中断）
3. 写 RX_ADDR_P0（5 字节，发射方地址）
4. 写 EN_RXADDR.ERX_P0 = 1（开 P0）
5. 写 RX_PW_P0（payload 字节数 0~32）
6. 写 EN_AA.ENAA_P0 = 1（如果回 ACK payload）
7. 写 RF_CH（同发射方）
8. 写 RF_SETUP（同发射方）
9. CE 拉高进入 RX 监听
10. 等待 IRQ.RX_DR = 1：
    - R_RX_PAYLOAD 读 payload
    - 写 STATUS.RX_DR = 1 清中断
```

### ACK payload 双向通信（发送端 + 接收端都要支持）

```text
发送端：
  1. 在 W_TX_PAYLOAD 写 A→B 数据
  2. CE 拉高启动 TX
  3. 收到 TX_DS 后，**立刻从 RX FIFO 读出 B 的 ACK payload**（如果有）

接收端：
  1. 收到 RX_DR 后，从 RX FIFO 读 A 的 payload
  2. 在 W_ACK_PAYLOAD pipe (0xA8) 写 B→A 数据
  3. 硬件在自动 ACK 包中塞这个数据
```

### 多 pipe 应用

nRF24L01+ 典型"1 主 6 从"星形组网：

```text
主机：
  - P0 = "主机地址"，用于收 6 个从机的 ACK payload
  - TX_ADDR = 从机 1 地址（要切换发谁就改 TX_ADDR）
  - 写 W_ACK_PAYLOAD 0xA8 + 0xAC 给 P0~P4 → 5 个从机各自的 ACK 槽

从机 X：
  - P0 = 主机地址（用于 ACK）
  - TX_ADDR = 主机地址
```

## 优点与限制

### 优点

- **成本极低**：1~3 RMB 拿到完整 2.4 GHz 收发器
- **学习曲线低**：SPI + 30 寄存器就能跑通，比 BLE 协议栈小一个数量级
- **功耗合理**：待机 ~10 µA，发射 < 14 mA，纽扣电池 CR2032 间歇通信可工作数月
- **延迟低**：硬件自动重发 + ACK payload，130~200 µs 完成一次"双向握手"
- **硬件链路层免写**：CRC、地址匹配、自动重发、ACK payload、6 pipe 全部片上
- **兼容国产**：SI24R1 / XL2400 / nRF24L01P 寄存器兼容，可以直接替换

### 限制

- **无加密**：地址匹配即可收，保密 = 0；应用层要做加密只能自己写（一般用 AES-128 软件加密 payload）
- **No authentication**：任何知道地址的人都可冒充发送（可以在应用层加 CRC / HMAC）
- **节点数受限**：6 pipe = 6 个"目标地址"，星形 1 主 6 从；要更多节点需要上层协议做地址复用 + 频道切换
- **半双工**：同一时间只能 TX 或 RX，ACK payload 是"伪装"的全双工，本质还是 TDM
- **2.4 GHz 拥挤**：与 Wi-Fi / BLE / ZigBee 共用 2.4 GHz，互相干扰
- **无 link quality indicator**：只有 RPD（接收功率检测），没有 BLE 那样的 RSSI / 丢包率统计
- **无 OTA 升级**：芯片本身没 bootloader，要远程升级需要外挂 MCU 跑应用层 OTA
- **无 FCC / ETSI 认证**：模块厂家认证，整机仍需测试；BLE / ZigBee 模块通常自带认证
- **寄存器版本陷阱**：nRF24L01（2006，无 + 号）不支持 ACK payload，国产 SI24R1 部分批次有兼容问题

## 典型应用

- **无线鼠标 / 键盘 / 手柄**：50~200 个 byte / 10 ms，鼠标移动 + 滚轮 + 按键包
- **四轴飞行器遥控**：遥控 4~16 通道 + 回传姿态，约 32 byte / 20 ms
- **玩具遥控**：车 / 船 / 飞机，最经典的 nRF2401 应用场景
- **无线串口透传模块**：淘宝"无线串口"商品多数基于 nRF24L01+ 兼容芯片
- **低功耗数据回传**：电池供电传感器定时上报温度 / 湿度 / GPS，CR2032 可用 1~2 年
- **板间通信**：两个 MCU 间替代 SPI/UART 长线，nRF2401 通过天线收发
- **简易 IoT 标签**：电子价签、资产追踪（成本极低，但需要上层协议做 inventory）
- **DIY 家用自组网**：智能家居传感器节点、自建小网络
- **PLC 无线控制板**：工业 24V 环境下的远程 IO 控制（nRF2401 抗 -40~+85°C）
- **教学实验**：物联网 / 嵌入式课程学生练手（学习曲线最低的 2.4 GHz 收发器）

## 与相关协议对比

### nRF2401 vs nRF24L01+ vs nRF905

| 项 | nRF2401（2003） | nRF24L01+（2008） | nRF905（< 1 GHz） |
| --- | --- | --- | --- |
| 频段 | 2.4 GHz | 2.4 GHz | 433 / 868 / 915 MHz |
| 速率 | 250 k / 1 Mbps | 1 / 2 Mbps | 50 kbps |
| Payload | 1~144 B | 1~32 B | 1~32 B |
| ShockBurst | 基础 | Enhanced | 类似 ShockBurst |
| ACK payload | ❌ | ✅ | ❌ |
| Auto-Retransmit | ❌ | ✅ | ❌ |
| SPI 接口 | 无（并行） | ✅ | ✅ |
| 状态 | 停产 | 在产 + 国产兼容 | 在产 |

新设计一律 nRF24L01+ / SI24R1 / XL2400 兼容芯片（寄存器、协议、引脚全兼容），nRF2401 老产品维护才需要。

### nRF2401 vs CC1101

| 项 | nRF2401 系 | CC1101 |
| --- | --- | --- |
| 频段 | 2.4 GHz | 315 / 433 / 868 / 915 MHz |
| 距离 | 短（2.4 GHz 衰减大） | 长（< 1 GHz 绕射好） |
| 抗干扰 | 一般（2.4 GHz 拥挤） | 好（sub-GHz 干扰少） |
| 成本 | 1~3 RMB | 3~10 RMB |
| 应用 | 室内短距 | 室外长距 |

**nRF2401 是"室内短距首选"，CC1101 是"室外长距首选"**。需要 1~2 km 距离 + 室外环境，CC1101 / SX1278（LoRa）更合适。

### nRF2401 vs ESP-NOW

ESP-NOW 是乐鑫 ESP32 / ESP8266 的私有协议，基于 Wi-Fi MAC 层：

| 项 | nRF2401 | ESP-NOW |
| --- | --- | --- |
| 协议基础 | 自有硬件链路 | Wi-Fi MAC |
| 距离 | 50~200 m | 100~300 m |
| 速率 | 1/2 Mbps | 1 Mbps（与 Wi-Fi 共用 PHY） |
| 加密 | 无 | AES-128（自带） |
| 节点 | 6 pipe | 20 个加密 peer |
| 待机功耗 | < 10 µA | > 1 mA（Wi-Fi 基带） |
| 成本 | 1~3 RMB | ESP32 整套 5~15 RMB |
| 学习曲线 | 极低 | 中（需 ESP-IDF） |

**nRF2401 适合"非 Wi-Fi 芯片的低成本板间通信"，ESP-NOW 适合"已经有 ESP32 但不想跑完整 Wi-Fi 协议栈"**。

### nRF2401 vs BLE（应用层选型）

| 场景 | 选 NRF2401 | 选 BLE |
| --- | --- | --- |
| 手机对接 | ❌ 手机没 NRF2401 | ✅ |
| 跨厂商互通 | ❌ 私有协议 | ✅ 标准 |
| 成本敏感 / 极致低价 | ✅ | ❌ |
| 学习嵌入式射频 | ✅ | ❌ |
| 需要认证 + 加密 | ❌（应用层加） | ✅ |
| 1 主 6 从星形 | ✅ | ✅ |
| 上千节点网状 | ❌ | ⚠️ BLE Mesh 较新 |
| < 50 ms 延迟 | ✅（< 1 ms） | ✅（7.5 ms 起） |

**手机/平板/笔记本互通必须 BLE，nRF2401 永远做不到**。

## 嵌入式产线典型故障

| 现象 | 优先检查 |
| --- | --- |
| 上电后 STATUS 读不到 0x0E | SPI 时序错 / CSN 没拉低 / 芯片未上电 / MISO 接错 |
| TX 出去对方收不到 | RF_CH 不一致 / 地址不匹配 / CRC 配置不一致 / 发射功率设 -18 dBm |
| RX_DR 中断不触发 | PRIM_RX 错设 / RX 地址错 / CE 没拉高 / RF_CH 错 / RX_PW_P0 = 0 |
| TX_DS 触发但 RX_DR 不触发 | EN_AA 没开 / 对方 EN_AA 没开 / 对方不在 RX 模式 |
| MAX_RT 一直触发 | 对方没收到 / 频道不一致 / 对方电源坏 / 重发间隔太短 |
| ACK payload 收不到 | FEATURE.EN_ACT_PAY 未开 / 对方没写 W_ACK_PAYLOAD / DYNPD 没开 |
| 距离近（< 10 m）就丢包 | 电源纹波大（VCC 跌落 < 3.0V）/ 模块本身虚焊 / 天线净空被金属件遮挡 |
| 同环境距离时好时坏 | 同频 Wi-Fi / 微波炉干扰 → 切到 RF_CH 75~125（2.475~2.525 GHz） |
| TX 时偶尔卡死 | TX FIFO 满 / FLUSH_TX 后才能写下一个 |
| RX 时偶尔丢一包 | RX FIFO 满（要 FLUSH_RX）/ ACK 写慢导致下一包错过 |
| 接收灵敏度差 | LNA_HCURR 没开 / RF_DR = 2 Mbps（1 Mbps 更稳）/ 天线净空 |
| 长时间运行后死机 | 看门狗未启 / 中断优先级错 / STATUS 寄存器写 1 清中断漏清 |
| CRC 校验失败 | 重发间隔太短被干扰 / SPI 速率太高读寄存器错 / 电源纹波 |
| 数据偶尔串字节 | SPI 时序错 / 片选时序 / 字节序错（确认 MSB） |
| 多节点同时发互相干扰 | 没有 CSMA/CD（自己应用层加退避算法）/ 改为时分复用 / 切频道 |
| 中断触发但 payload 全 0 | R_RX_PL_WID 没读 / 动态 payload 模式没开 / FIFO 未读空 |

## 调试步骤（从硬件到协议）

1. **电源**：用万用表量 VCC 是否稳定 3.3V ±0.1V，发射时跌落 < 0.2V；10 µF 钽 + 100 nF 瓷片是否到位
2. **SPI 基础读寄存器**：上电后 STATUS 应该 = 0x0E（默认 CONFIG + TX FIFO 空 + PWR_UP=0）
3. **写 CONFIG.PWR_UP=1**：1.5 ms 后 STATUS bit1（PWR_UP）变 1
4. **写 TX_ADDR + RX_ADDR_P0**：再读回来对比，确认写入正确
5. **单向 TX 测试**：写 W_TX_PAYLOAD → 拉高 CE 10 µs → 看 STATUS.TX_DS 是否变 1
6. **单向 RX 测试**：用已知发射器 + CE 拉高 → 看 STATUS.RX_DR 是否变 1
7. **双向 ACK payload 测试**：双方都开 EN_AA + FEATURE.EN_ACT_PAY → 一边发 + 另一边 ACK payload
8. **距离测试**：空旷 50 m / 100 m / 200 m 看丢包率（自动重发 + RPD 检测）
9. **同频干扰**：开 Wi-Fi 或微波炉看丢包率（验证避让策略）
10. **长时间运行**：CR2032 电池供电，1 包/秒，1~2 周看电池电压

## 实战检查清单

- 电源 3.3V ±0.1V，10 µF 钽 + 100 nF 瓷片紧贴 VCC
- SPI 时钟 ≤ 8 MHz，CPOL=0, CPHA=0，MSB 先发
- CE 启动 TX 至少拉高 10 µs
- 上电 PWR_UP=1 后等 ≥ 1.5 ms 才能进入 TX/RX
- TX_ADDR / RX_ADDR_P0 严格 5 字节一致（双方均写）
- RF_CH 同 RF_CH（频道值相同）
- RF_DR 相同 RF_DR（速率匹配）
- EN_AA.ENAA_P0 必须双方都开（双向 ACK 必要条件）
- RX_PW_P0 与 TX payload 长度匹配（不用动态 payload 时）
- MAX_RT 触发后必须写 STATUS = 0x10 清中断 + FLUSH_TX 清 FIFO
- 状态轮询 OR 中断二选一，**不要混用**（容易漏清中断标志）
- 中断优先级：RX_DR > TX_DS > MAX_RT
- 2.4 GHz 拥挤环境切到 RF_CH 75~125 避让 Wi-Fi
- 多节点星形网用 1 主 + 6 从，上层做时分调度
- 应用层加密 / HMAC / 重发防伪（nRF2401 硬件不做）
- PCB 天线模块的天线净空 ≥ 5 mm，下方禁止铺铜
- 看门狗 + 长时间运行死机保护
- 模块认证：UL / FCC / ETSI / SRRC（出货产品必须）

## 协议外延与生态

- **国产兼容芯片**：SI24R1（Silicon Labs 同名 / 中科微）、XL2400（XinLu）、nRF24L01P（Nordic 原厂）
  - 寄存器、引脚、协议 100% 兼容
  - SI24R1 部分批次 2 Mbps 不稳，建议降到 1 Mbps
  - XL2400 出货量最大，性价比最高
- **无线串口模块**：淘宝/LCSC 上的"无线串口"商品，多数是 nRF24L01+ + STM8 / STM32 跑 SI24R1 兼容固件，对外提供 UART
- **Arduino 库**：RF24（github.com/nRF24/RF24）最常用，封装 ShockBurst / 多 pipe / ACK payload
- **Linux 驱动**：树莓派 / i.MX / 全志芯片的 SPI 控制器 + RF24 内核模块（`drivers/net/nrf24.c`，老内核）
- **OpenOCD / 调试**：nRF24L01+ 本身没有 JTAG/SWD，只能 SPI 命令寄存器读写调试

## 选型决策树

```text
需要 2.4 GHz 短距收发
├── 节点需要手机对接 → BLE
├── 节点 ≥ 100 个网状 → ZigBee / Thread / Matter
├── 节点 ≤ 6 个星形 + 成本极致 + 不需加密 → nRF2401 系 ✅
├── 节点 6~20 个星形 + 需要加密 → BLE 私有协议
├── 节点长距离 km 级 → LoRa / CC1101
├── 节点吞吐 > 1 Mbps → Wi-Fi / BLE 2M PHY
└── 节点已有 ESP32 → ESP-NOW
```
