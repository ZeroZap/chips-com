# UART Deep Dive

## 目标

本文深入 UART 工程细节，重点解决“能跑”和“稳定量产”之间的问题：波特率误差、采样容差、硬件流控、DMA 接收、协议分帧、低功耗唤醒和现场排障。

## UART 接收为什么能不同步

UART 没有独立时钟线。接收端依靠起始位同步：

```text
空闲高电平 -> 检测下降沿 -> 认为起始位开始 -> 按本地波特率采样后续 bit
```

这意味着 UART 的可靠性依赖：

- 双方波特率足够接近。
- 起始位边沿清晰。
- 一帧内累计时钟误差不能太大。
- 接收端采样点落在每个 bit 的稳定区域。

## 过采样

很多 UART 控制器使用过采样，例如：

```text
16x oversampling
8x oversampling
```

以 16x 为例，接收端在一个 bit 时间内有 16 个采样节拍，可以更稳地定位 bit 中心。

常见做法：

```text
检测起始位下降沿
等待半个 bit 时间
在 bit 中间附近采样
后续每隔一个 bit 时间采样一次
```

过采样越高，抗抖动能力通常越好，但对时钟和硬件设计也有具体限制。

## 波特率误差

UART 双方的实际波特率不可能完全一致。

误差来源：

- 晶振精度。
- 内部 RC 振荡器误差。
- 分频寄存器不能精确整除。
- 温度和电压漂移。
- USB 转串口工具实际误差。

常见经验：

```text
总误差最好控制在 2% 以内
高速或长帧时应更严格
内部 RC 时钟不校准时不适合高可靠高速 UART
```

如果出现稳定乱码，优先检查：

```text
系统时钟配置
UART 分频计算
实际波特率
对端参数
```

## 帧越长，误差越敏感

UART 每帧只在起始位重新同步。

例如 `8N1` 一帧是：

```text
1 start + 8 data + 1 stop = 10 bit
```

如果使用：

```text
8E2
```

帧更长，累计误差更大。

长帧配置、低质量时钟、高波特率组合在一起时，更容易出现边界采样错误。

## 校验位能解决什么

UART parity 只能检测部分单 bit 错误。

常见配置：

```text
None：无校验
Even：偶校验
Odd：奇校验
```

它不能解决：

- 丢字节。
- 字节顺序错。
- 多 bit 错误刚好校验通过。
- 帧边界混乱。
- 应用层数据完整性。

工业协议通常还会加：

```text
CRC16
Checksum
Length
Sequence
Timeout
```

## 硬件流控 RTS/CTS

高速 UART 或接收端处理能力不稳定时，可以使用硬件流控。

常见信号：

```text
RTS：Request To Send
CTS：Clear To Send
```

用途：

```text
接收端快满时通知发送端暂停
接收端有空间时允许继续发送
```

适合：

- 大量连续数据。
- 模块 AT 通信。
- 蓝牙/Wi-Fi/蜂窝模块。
- 操作系统调度不可控的场景。

如果没有流控，必须保证：

```text
接收中断/DMA 足够快
缓冲区足够大
协议允许重传或限速
```

## DMA 接收

高吞吐 UART 推荐 DMA 接收。

常见模式：

```text
DMA circular buffer
UART IDLE interrupt
ring buffer
```

典型流程：

```text
DMA 持续把 UART 数据写入环形缓冲区
IDLE 中断表示一段数据暂时结束
软件根据 DMA 写指针取出新增数据
协议解析器按状态机处理帧
```

注意点：

- IDLE 不等于完整协议帧，只表示线路空闲。
- DMA 缓冲区不能太小。
- 读写指针要处理回绕。
- Cache 系统要处理缓存一致性。
- 错误中断要清除 ORE/FE/NE 等标志。

## 常见 UART 错误标志

不同 MCU 命名不同，但常见有：

```text
ORE：Overrun Error，接收溢出
FE：Framing Error，停止位错误
PE：Parity Error，校验错误
NE：Noise Error，噪声错误
```

排查方向：

| 错误 | 可能原因 |
| --- | --- |
| ORE | 中断太慢、DMA 未开、缓冲区满 |
| FE | 波特率错、电平异常、停止位不匹配 |
| PE | 校验位配置不一致或数据损坏 |
| NE | 干扰、线缆过长、边沿质量差 |

## 协议分帧设计

UART 是字节流，不知道哪里是一条消息。

可靠协议建议包含：

```text
SOF：起始标记
LEN：长度
TYPE/CMD：命令或类型
SEQ：序号，可选
PAYLOAD：数据
CRC：校验
```

示例：

```text
AA 55 | LEN | CMD | SEQ | PAYLOAD | CRC16
```

解析器应支持：

- 从任意字节流中重新同步。
- 长度异常丢弃。
- CRC 错误丢弃。
- 超时重置状态机。
- 序号去重或重传。

## 文本协议和二进制协议

文本协议优点：

- 人能直接看。
- 串口工具方便调试。
- 适合命令行和 AT 指令。

文本协议缺点：

- 开销大。
- 解析复杂度可能被低估。
- 二进制数据需要转义或编码。

二进制协议优点：

- 高效。
- 长度明确。
- 适合嵌入式设备间通信。

二进制协议缺点：

- 人眼不易调试。
- 需要协议解析工具。
- 要处理转义、同步和 CRC。

## 低功耗唤醒

UART 可用于低功耗唤醒，但要注意：

- 唤醒后时钟是否稳定。
- 第一个字节是否会丢。
- 是否需要前导字节。
- RX 引脚电平是否能触发唤醒。
- 波特率时钟源在低功耗模式下是否可用。

常见策略：

```text
发送端先发 wakeup byte
等待目标唤醒
再发送正式协议帧
```

## 量产测试建议

UART 量产测试可以覆盖：

1. TX/RX 回环测试。
2. 标准波特率通信测试。
3. 高低温下通信稳定性。
4. 长时间连续收发压力测试。
5. 错误帧和 CRC 检测测试。
6. 断线重连测试。
7. RS485 方向控制测试。
8. 模块流控测试。

## 深度检查清单

- 实际波特率误差已测量或计算。
- 时钟源精度满足目标波特率。
- 接收使用中断或 DMA，不依赖长时间轮询。
- 错误标志有统计和清除逻辑。
- 协议有长度、校验、超时和重同步。
- 高吞吐场景已评估 RTS/CTS 或限速。
- 低功耗唤醒不会丢正式帧。
- 现场日志能区分物理层、UART 层和协议层问题。

## UART 故障树

把 UART 通信异常的所有可能根因画成一张决策树, 从现场现象一路推到具体验证手段。

```text
现象: UART 通信失败
  |
  +-- 抓波形
        |
        +-- 完全没数据
        |     -> TX/RX 接反 / 没共地 / 串口错 / 工具参数错
        |     -> 验证: 交换 TX/RX, 量两端 GND, 改串口工具
        |
        +-- 乱码 (收到的数据是预期值的移位)
        |     -> 波特率错 / 晶振不准 / 过采样率错
        |     -> 验证: 量实际 baud, 查晶振负载电容
        |
        +-- 偶发丢字节
        |     -> FIFO 溢出 / 缓冲区小 / 流控未开
        |     -> 验证: 量 overrun 错误, 开 DMA + 环形缓冲
        |
        +-- 高速丢包
        |     -> CPU 来不及读 / DMA 未用 / FIFO 深度不够
        |     -> 验证: 降速看是否消失, 开硬件流控
        |
        +-- 多设备总线冲突
        |     -> TX 线被两个设备同时驱动 (RS485 方向控制错)
        |     -> 验证: 查 RS485 DIR GPIO 时序
        |
        +-- 校验错
        |     -> parity 配错 / 线缆干扰 / 长距离没屏蔽
        |     -> 验证: 短距离测试, 改屏蔽线
        |
        +-- 只能收不能发
        |     -> TX 接线 / pinmux / 方向控制
        |     -> 验证: 单独测 TX, 查 RS485 DIR
        |
        +-- 接上就复位
              -> 电平不兼容 / ESD / 电源短路
              -> 验证: 量两端电平, 拔插测试
```

### 故障树对应的快速判定

| 现象 | 一句话定位 | 首选动作 |
| --- | --- | --- |
| 完全没数据 | TX/RX 接反 / 没共地 | 交换 TX/RX, 查 GND |
| 乱码 | 波特率错 / 晶振不准 | 量 baud, 校准晶振 |
| 偶发丢字节 | FIFO 溢出 / 缓冲区小 | 开 DMA + 环形缓冲 |
| 高速丢包 | CPU 来不及 / 流控未开 | 开硬件流控或降速 |
| 校验错 | parity 配错 / 干扰 | 短距离测试, 改屏蔽 |
| 只能收不能发 | 方向控制错 | 查 RS485 DIR |
| 多设备冲突 | RS485 方向控制错 | 查 DIR 时序 |
| 接上就复位 | 电平冲突 / ESD | 量两端电平, 加 TVS |

## 波特率计算与误差

### 公式

```text
实际 baud = UART 时钟 / (16 * (BRR 寄存器的整数部分 + 分数部分))
或
实际 baud = UART 时钟 / 分频系数
```

STM32 例: APB1 时钟 36 MHz, 115200 baud:

```text
分频系数 = 36000000 / 115200 = 312.5
整数部分 = 312
分数部分 = 0.5 * 16 = 8

实际 baud = 36000000 / (16 * 312.5) = 72000
```

**误差**: BRR 寄存器有量化误差, 误差 < 1% 可接受。

### 误差容忍度

| 帧长 (bit) | 接收端最大累积误差 | 典型场景 |
| --- | --- | --- |
| 10 (8N1) | 5% | 短消息 |
| 11 (8N2) | 4.5% | 普通 |
| 12 (8E1 + 1) | 4% | 长消息 |
| 100 (10 字节) | 0.5% | 大数据块 |

**关键**: 高速 + 长帧, 误差容忍度更严, 用精度更高的晶振。

### 晶振选择

```text
内部 RC 振荡器:   误差 1-2% (调试用)
外部晶振 (8 MHz): 误差 20 ppm (~0.002%)
外部晶振 (16 MHz): 误差 20 ppm
温补晶振 (TCXO):  误差 1-5 ppm (工业级)
```

**推荐**: 产线产品必须用外部晶振, 内部 RC 只能用于 boot 阶段。

## UART 帧格式细节

### 完整帧结构 (8N1)

```text
idle  ┐
      ↓ 1 bit (start, always 0)
bit0  |
bit1  |
bit2  |
bit3  | 8 data bits (LSB first)
bit4  |
bit5  |
bit6  |
bit7  |
      ↓ 1 bit (stop, always 1)
idle  ┘
```

**关键**:
- 空闲态为高电平
- 起始位为低电平
- 数据 LSB 先发
- 停止位为高电平

### 1 vs 2 停止位

```text
1 停止位: 标准, 多数设备
2 停止位: 慢速 (110 baud) 老设备, 偶尔用
         或留额外时间给接收方处理
```

**注意**: 2 停止位不增加可靠性, 多数场景用 1 停止位。

### 校验位

```text
None (N):   无校验
Even (E):   数据 + parity 总共有偶数个 1
Odd (O):    数据 + parity 总共有奇数个 1
```

**关键**: 校验位只能检测**单 bit** 错误, 不能纠错。CRC 才能纠错。

## UART 时序详细

### 发送时序

```text
写入 TXDR -> 等 TXE=1 -> 写入下一字节 -> ...
```

### 接收时序

```text
start bit (falling edge) -> 等待 0.5 bit (定位中心)
                         -> 采样 bit0
                         -> 等待 1 bit
                         -> 采样 bit1
                         -> ...
                         -> 等待 1 bit
                         -> 采样 bit7
                         -> 等待 1 bit
                         -> 采样 stop bit
                         -> RXNE=1
```

**过采样**: 多数 MCU 用 16x 过采样 (每位采 16 次), 容忍度更高。

### 中断时序

```text
RXNE (接收完成) -> 中断
TXE (发送 buffer 空) -> 中断
TC (发送完成) -> 中断 (适合 RS485 方向控制)
```

**关键**: 发送完成 (TC) 和发送 buffer 空 (TXE) 不同, 方向控制要用 TC, 不用 TXE。

## UART 错误处理

### 错误类型

```c
typedef enum {
    UART_ERR_NONE         = 0,
    UART_ERR_OVERRUN      = 1,  // ORE: FIFO 溢出
    UART_ERR_PARITY       = 2,  // PE: 校验错
    UART_ERR_FRAMING      = 4,  // FE: 帧错 (停止位没收到)
    UART_ERR_NOISE        = 8,  // NE: 噪声
    UART_ERR_BREAK        = 16, // 长时间低电平
} uart_err_t;
```

### 错误处理策略

```text
ORE (溢出):  严重, 至少丢 1 字节, 必须清 + 重新同步
PE (校验):  通常是噪声, 丢弃当前字节, 继续接收
FE (帧错):  波特率错或噪声, 重新同步波特率
NE (噪声):  瞬时干扰, 丢弃当前字节
Break:      诊断信号, 上报 + 重新同步
```

**关键**: 任何错误都必须**清错误标志**, 否则后续接收被抑制。

## UART 状态机

```text
IDLE
  -> (收到数据) -> RX_BUSY
RX_BUSY
  -> (1 字节完成) -> RX_BUSY (继续) / RX_DONE (最后一字节)
RX_DONE
  -> (协议层处理) -> IDLE
  -> (错误) -> RX_ERROR
RX_ERROR
  -> (清错误) -> IDLE

TX_IDLE
  -> (写入 TXDR) -> TX_BUSY
TX_BUSY
  -> (TXE) -> TX_BUSY (继续) / TX_DONE (最后一字节)
TX_DONE
  -> (TC, 适合 RS485 切回接收) -> TX_IDLE
```

## UART 调试技巧

### 1. 逻辑分析仪必备信号

```text
- TX: 看发送时序
- RX: 看接收时序
- RTS / CTS (如果用流控)
- DIR (如果 RS485)
- GPIO (用于触发): 标记事务开始
```

### 2. 示波器看 UART

```text
- TX 波形: 一帧 10 bit (8N1), idle 高
- 起始位下降沿触发
- 量每位时长, 算 baud
- 量化误差 < 1% 才稳定
```

### 3. 协议解码

```text
- 逻辑分析仪: UART 协议解码, 直接看到数据
- Saleae / Kingst / 总线分析仪
- 配置: baud, parity, stop bits
- 看是否是预期的 ASCII / 二进制
```

## UART 错误码设计

```c
typedef enum {
    UART_OK              = 0,
    UART_ERR_TIMEOUT     = -1,   // 等待超时
    UART_ERR_FRAMING     = -2,   // 帧错
    UART_ERR_PARITY      = -3,   // 校验错
    UART_ERR_OVERRUN     = -4,   // 溢出
    UART_ERR_NOISE       = -5,   // 噪声
    UART_ERR_DMA         = -6,   // DMA 失败
    UART_ERR_BREAK       = -7,   // Break 条件
    UART_ERR_BAUD        = -8,   // 波特率不可配置
    UART_ERR_PROTOCOL    = -9,   // 协议层错
} uart_err_t;
```

## UART vs SPI vs I2C 选型决策

```text
选 UART 当:
  - 点对点异步通信
  - 调试口 (printf / log)
  - 异步长距离 (RS485 / RS422)
  - 不需要时钟线
  - 板间 / 设备间通用接口
  - 接受外加电平转换器

选 SPI 当:
  - 高速 (> 1 MHz) 同步
  - 短距离 (< 30cm)
  - 接受 4-7 根引脚
  - 全双工

选 I2C 当:
  - 板内低速 (<= 400 kHz)
  - 多个设备共享总线
  - 2 根引脚
  - 接受开漏 + 上拉

选 CAN 当:
  - 汽车 / 工业
  - 多节点, 强实时
  - 强抗干扰
  - 距离 > 1m
```

## 7 条 UART 常见错误

| # | 错误 | 后果 |
| --- | --- | --- |
| 1 | TX/RX 接反 | 完全没数据 |
| 2 | 没共地 | 乱码或无数据 |
| 3 | 波特率不匹配 | 乱码 |
| 4 | 没清错误标志 | 后续接收被抑制 |
| 5 | RS485 方向控制时序错 | 数据丢失 / 冲突 |
| 6 | 不用 DMA, 高速丢包 | 偶发丢字节 |
| 7 | 协议无帧边界 | 字节流错乱 |

## 产线 UART 验收清单

- [ ] 波特率匹配, 误差 < 1%
- [ ] TX/RX 方向对, GND 共地
- [ ] 引脚复用配好
- [ ] 接收用中断或 DMA
- [ ] 错误标志有统计和清除
- [ ] RS485 方向控制时序对
- [ ] 协议有帧边界 (SOF + LEN + CRC)
- [ ] 缓冲区足够 (>= 256 字节)
- [ ] 高速 (>= 1M) 开硬件流控
- [ ] 老化测试 (1000 小时)
