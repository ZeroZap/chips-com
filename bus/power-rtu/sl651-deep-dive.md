# SL 651-2014 Deep Dive

## 目标

本文深入 SL 651 工程细节，重点解决链路帧与信息帧的状态机、要素编码、BCD 数据格式、自报 / 召测 / 控制命令链路、GSM 短信备份、多信道策略、省级平台对接差异和现场排障。

```text
物理层：4G / GSM / 北斗 / 光纤 / 卫星 IoT
```

## 帧结构详解

### 链路帧

```text
F1/F2/F3/F4 + 中心站地址 + 测站地址 + 链路标识 + CRC + 帧尾
```

帧首编码：

```text
F1 = 0x46 0x31（链路维持）
F2 = 0x46 0x32（链路建立）
F3 = 0x46 0x33（链路释放）
F4 = 0x46 0x34（链路测试）
```

帧尾 = 0x03

链路标识：

```text
0x10  链路建立确认
0x11  链路维持应答
0x12  链路释放确认
0x13  测试应答
```

### 信息帧

```text
STX + LEN + 中心站地址 + 测站地址 + FC + 数据 + CRC16 + ETX
```

字段说明：

```text
STX = 0x02
LEN = 1 字节
  表示从 STX 后第一个字节到 ETX 前字节数
  LEN = 中心站地址字节数 + 测站地址字节数 + 1（FC）+ 数据段字节数 + 2（CRC16）

中心站地址：BCD 编码 1-2 字节
  小中心站（10 以内）：1 字节
  大型中心站：2 字节

测站地址：BCD 编码 1-2 字节
  同上

数据段：可变
CRC16：CRC-16/MODBUS 同款
ETX = 0x03
```

## CRC16 计算

SL 651 CRC16 与 Modbus CRC16 相同算法：

```text
多项式：0xA001
初值：0xFFFF
低字节在前
```

工程实现：

```text
uint16_t crc = 0xFFFF;
for (i = start; i < end; i++) {
    crc ^= data[i];
    for (j = 0; j < 8; j++) {
        if (crc & 1) {
            crc = (crc >> 1) ^ 0xA001;
        } else {
            crc >>= 1;
        }
    }
}
```

## 功能码（FC）完整列表

监测类（测站 → 中心）：

```text
0x30  自报小时数据
0x31  自报分钟数据
0x32  加报
0x40  状态上报
```

控制类（中心 → 测站）：

```text
0x33  召测命令
0x36  设置参数
0x38  时间校准
0x3A  控制命令（闸门、泵等）
0x50  应急广播
```

应答类（测站 → 中心）：

```text
0x34  召测应答
0x35  控制应答
0x37  设置参数应答
0x39  时间校准应答
0x3B  控制应答
0x41  状态查询应答
```

## 报文解析步骤

```text
1. 收到 STX（0x02）→ 启动
3. 读 LEN（1 字节）
5. 读 LEN - 1 个字节（包括 ETX）
7. 验证 STX 位置正确
9. 解析 中心站地址、测站地址、FC
11. 读数据段（FC 决定格式）
13. 读 CRC16
15. 读 ETX（0x03）
17. 验证 CRC16
19. 发送应答或下一报文
```

工程实现：

```text
parser 状态机：
  IDLE → WAIT_STX → READ_LEN → READ_ADDR → READ_FC → READ_DATA → READ_CRC → WAIT_ETX → IDLE
```

## 要素编码详解

SL 651 要素编码 4 字节：

```text
[要素类型 1 字节][测量类型 1 字节][数值字节数][小数位]
```

要素类型：

```text
0x00  雨量
0x10  水位
0x20  流量
0x30  流速
0x40  含沙量
0x50  闸位
0x60  蒸发量
0x70  水温
0x80  气温
0x90  湿度
0xA0  风力
0xB0  风向
0xC0  电源电压
0xD0  设备状态
```

测量类型：

```text
0x01  瞬时值
0x02  累计值
0x03  平均值
0x04  最大值
0x05  最小值
```

数值字节数：

```text
1-4 字节 BCD
```

小数位：

```text
编码位数（0-4）
```

### 雨量 5.0 mm

```text
0x00 0x01 0x02 0x01
[0x00][0x01][0x02][0x01][0x00][0x32]
要素类型 + 测量类型 + 2 字节数值 + 1 位小数 + 50 = 5.0 mm
```

### 水位 23.45 m

```text
0x10 0x01 0x03 0x02
[0x10][0x01][0x03][0x02][0x02][0x34][0x50]
要素类型 + 测量类型 + 3 字节数值 + 2 位小数 + 2345 = 23.45 m
```

### 流量 50.32 m³/s

```text
0x20 0x01 0x04 0x02
[0x20][0x01][0x04][0x02][0x00][0x50][0x32][0x00]
要素类型 + 测量类型 + 4 字节数值 + 2 位小数 + 503200 (BCD) = 50.32 m³/s
```

## GSM 短信备份

短信编码：

```text
短信内容 = SL 651 信息帧（去 STX/ETX）
PDU 7-bit 编码
中心站号：固定 SIM 卡号
```

AT 命令流程：

```text
1. AT+CMGF=0  PDU 模式
3. AT+CSCS="GSM"
5. AT+CMGS=<长度>
7. PDU 数据（包含中心站号 + 内容）
9. Ctrl-Z 发送
```

实际 PDU 格式：

```text
0x11 短信中心 + 0x00 协议标识
0x01 短信发送 + 0xXX 信息类型
+ 中心站号（PDU BCD）
+ TP-PID
+ TP-DCS（7-bit）
+ TP-VP（有效期）
+ UDL（用户数据长度）
+ UD（SL 651 信息帧）
```

工程实现：

```text
1. 编码 SL 651 信息帧（去 STX/ETX）
3. 7-bit 编码
5. 计算 UDL（7-bit 单位）
7. 计算 UDL 七元组长度
9. 拼装 PDU
10. AT 指令发送
11. 返回 +CMGS 响应
```

## 多信道状态机

```text
STATE_INIT → 初始化所有信道
STATE_TCP_OK → 主信道 TCP
STATE_TCP_FAIL → 主信道失败
  → STATE_GSM → GSM 短信
    STATE_GSM_OK → TCP 恢复
    STATE_GSM_FAIL → 北斗
      STATE_BD_OK → TCP 恢复
      STATE_BD_FAIL → 本地存储
```
