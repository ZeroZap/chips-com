# SL 651-2014 Practical Guide

## 目标

本文用于把 SL 651 工程链路调通：TCP 接入、链路建立、自报 / 召测 / 控制应答、GSM 短信备份和省级水文平台对接。

## TCP 接入

```text
测站（client）→ TCP:port → 中心站（server）
```

常见端口：
- 5000（多数省份）
- 8000（部分省份）
- 8801（特定省份）

工程注意：

- 不同省份端口不同，部署前必须确认。
- 部分省份需要 VPN / 专网。

## 帧格式速记

### 链路帧

```text
F1/F2/F3/F4 + 中心站地址 + 测站地址 + 链路标识 + CRC + 帧尾
```

帧首：

```text
F1 = 0x46 + 0x31（链路维持）
F2 = 0x46 + 0x32（链路建立）
F3 = 0x46 + 0x33（链路释放）
F4 = 0x46 + 0x34（链路测试）
```

帧尾：

```text
ETX = 0x03
```

### 信息帧

```text
STX + LEN + 中心站地址 + 测站地址 + FC + 数据 + CRC16 + ETX
```

字段：

```text
STX = 0x02
LEN = 1 字节（不含 STX，含 ETX）
中心站地址 = 1-2 字节 BCD
测站地址 = 1-2 字节 BCD
FC = 1 字节（功能码）
数据 = 可变
CRC16 = 2 字节
ETX = 0x03
```

## 报文示例（十六进制）

### 链路建立（测站 → 中心站）

```text
F2 0x01 0x02 0x10 CRC ETX
```

实际：

```text
0x46 0x32 0x01 0x02 0x10 0xXX 0xXX 0x03
```

### 链路建立确认（中心站 → 测站）

```text
F2 0x01 0x02 0x10 CRC ETX
```

### 自报小时数据（FC=0x30）

测站 → 中心站：

```text
0x02 0x18 0x01 0x02 0x30
   24 09 18 10 15  时间
   05 00 00 00  雨量 5.00 mm
   23 45 00 00  水位 23.45 m
   50 32 00 00 00  流量 50.32 m³/s
CRC
0x03
```

### 召测（FC=0x33）

中心站 → 测站：

```text
0x02 LEN 0x01 0x02 0x33 0x01 CRC 0x03
```

0x01 = 召测所有要素。

### 召测应答（FC=0x34）

```text
0x02 LEN 0x01 0x02 0x34
   24 09 18 10 20  时间
   0x01 0x05 00 00  雨量 5.00
   0x10 0x01 23 45 00 00  水位
   0x20 0x01 50 32 00 00 00  流量
CRC
0x03
```

### 时间校准（FC=0x38）

```text
0x02 LEN 0x01 0x02 0x38
   24 09 18 10 25 00  时间
CRC
0x03
```

## 要素编码速查

```text
0x00  雨量
0x10  水位
0x20  流量
0x30  流速
0x40  含沙量
0x50  闸位
0x60  蒸发量
0x70  水温
0x80  气温
0x90  湿度
0xA0  风力
0xB0  风向
0xC0  电源电压
```

每个要素的测量类型编码：

```text
0x01  瞬时值
0x02  累计值
0x03  平均值
0x04  最大值
0x05  最小值
```

## 数据格式

水文要素数据编码：

```text
数据 = 要素类型 + 测量类型 + 数值 + 小数位

雨量 5.0 mm：
  0x00 0x01 0x00 0x00 0x05 0x00
  要素类型 + 测量类型 + 0.1 mm 单位精度 + 5 * 10 = 50 = 0x00 0x32

实际工程：BCD 编码 + 字节数固定
```

## 通信流程

### 链路建立

```text
1. 测站连接中心站 TCP
3. 测站发 F2 链路建立
5. 中心站回 F2 链路建立确认
9. 进入业务交互
```

### 链路维持（心跳）

```text
测站每 1-5 分钟发 F1
中心站回 F1
超时 → TCP 重连
```

### 自报

```text
定时自报（FC=0x30 / 0x31）：每固定周期
加报（FC=0x32）：实时触发
```

### 召测应答

```text
中心站发 FC=0x33 + 召测类型
测站发 FC=0x34 + 召测数据
```

### 控制应答

```text
中心站发 FC=0x3A + 控制内容
测站发 FC=0x3B + 控制结果
```

### 时间校准

```text
中心站发 FC=0x38 + 时间
测站发 FC=0x39 + 应答
```

### 设置参数

```text
中心站发 FC=0x36 + 参数内容
测站发 FC=0x37 + 设置结果
```

## GSM 短信备份

工程实现：

```text
1. TCP 连接失败 → 切到短信
3. 短信内容 = SL 651 信息帧（去 STX/ETX，加 PDU 头）
5. 短信编码：7-bit 编码
7. 中心站号：因本号
10. 读取订单通过 ATINU + MDCMGS
```

短信手机卡要求：
- 短信发送 SIM 卡有信号。
- 中心站 SIM 卡开放短信接收。
- 短信中心号预配置。

## 多信道备份策略

```text
主信道：TCP / 4G
备份 1：GSM 短信
备份 2：北斗短报文
备份 3：卫星 IoT
```

工程实现：

```text
状态机：
  TCP_OK → 主信道
  TCP_FAIL_30s → GSM 短信
  GSM_FAIL_60s → 北斗
  ALL_FAIL → 本地存储 + 重连
```

## 加报阈值

工程常见加报阈值：

```text
雨量：累计 5 mm（可配置 1-10 mm）
水位：变幅 0.05 m / 5 min
流量：变幅 10%
闸位：变幅 5 cm
```

- 短信调试：AT 命令 + 短信猫。

## 调试步骤

1. 确认测站地址 / 中心站地址已注册。
2. TCP 连接到中心站（确认端口）。
3. 发链路建立 F2，确认中心站确认。
4. 发链路维持 F1，确认中心站回应。
5. 发自报 FC=0x30，确认收到。
7. 发控制 FC=0x3A，确认收到。
8. 时间校准 FC=0x38，确认生效。
9. 切 GSM 短信备份，确认能发送。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| TCP 连接失败 | IP / 端口 / 4G 信号 |
| 链路建立失败 | 测站地址 / 中心站地址错 |
| 自报收不到 | FC / 时间 / 要素编码 |
| 召测无应答 | 流量超负荷 |
| GSM 短信失败 | SIM 卡 / 信号 / 短信中心号 |
| CRC 不一致 | 心字算反 |
| 中心站不存数据 | 要么不对应、要素代码错 |
| 多测站冲突 | TCP 端口 / 测站地址唯一 |

## 实战检查清单

- TCP 端口与省级一致。
- 测站地址 / 中心站地址 BCD 编码正确。
- 链路建立 F2 流程跑通。
- 链路维持 F1 心跳正常。
- 自报周期符合省级要求。
- 召测应答能正常返回。
- 控制命令能正确应答。
- 时间校准能正常执行。
- 设置参数能生效。
- 加报阈值合理。
- 多信道备份（GSM / 北斗）。
- 短信备份信道正常。
- CRC 计算正确。
- 要素编码正确。
