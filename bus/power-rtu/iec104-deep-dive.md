# IEC 60870-5-104 Deep Dive

## 目标

本文深入 IEC 104 协议栈细节，重点解决 APCI 字节序、I/S/U 格式状态机、k/w/t 参数联动、ASDU 解析、CP56 时间、双点命令选择执行撤销、突发上传策略和现场排障。

## 协议栈分层

```text
应用层：ASDU（IEC 101 共用）
表示层：APCI（启动字符 + 长度 + 控制域）
传输层：TCP（端口 2404）
网络层：IP
链路层：以太网有
物理层：100BASE-TX / 光纤 / 4G
```

注意 IEC 104 复用 IEC 101 的 ASDU 定义，但传输层从异步串行换成 TCP 字节流。字节序问题变得关键。

## APCI 字节序

APCI 启动字符 = `0x68`，长度字段表示 APDU 剩余字节数（不含启动字符本身）：

```text
68 [Length] [Control4] [ASDU]
```

长度字段自身占 1 字节，但 Length 值指示的是 APDU 总字节数减去 2（启动字符 + 长度字段）。

最大 APDU 长度限制：

```text
APCI 长度字段 1 字节 → 最大 255 字节
APDU 总长 = 2 + Length
```

工程实现常见做法：

- 收 buffer 不小于 256 字节。
- 解析逻辑先识别 0x68，然后按 Length 读取后续字节。

## 控制域详解（4 字节）

```text
I 格式：低字节第一，N(S) 15-0 高 7 位 + bit 0 = 0
          高字节低 4 位 = N(S) 15-12，高 4 位 = 0
          N(R) 类似

S 格式：bit 0 = 1（保留）
          高字节第二低字节 = N(R) 低 8 位
          高字节第一 = N(R) 高 8 位 + 控制位

U 格式：bit 0 = 1（保留）
          bit 1 = 0
          子功能在字节 1 bit 0/1
```

更精确描述（IEC 104:2000）：

```text
字节 1：N(S) 低 8 位（I）或子功能 / 测试位（U）
字节 2：N(S) 高 8 位（I）或子功能标识（U）
字节 3：N(R) 低 8 位（I/S）
字节 4：N(R) 高 8 位（I/S）
```

序号 N(S) / N(R) 是低字节在前。

## 三种 APDU 状态机

RTU 侧应维护：

```text
STOPPED：未启动数据传送
STARTED：可收发 ASDU

I 帧收到 → 累加 N(R)
STARTED：所有 I 帧都需要 S 帧确认
S 帧收到 → 确认累计接收
```

## k / w / t 参数联动

k 值：允许未确认 I 帧的最大数量（RTU 限制）

- 当 RTU 已发送未确认数达到 k 时，必须等待 S 帧才能继续发。
- 主站超过 k 限速后必须暂停发送。

w 值：最新接收确认序号

- RTU 收到 I 帧后，最迟收到 w 个 I 帧必须发 S 帧确认。
- 主站类似逻辑。

t1：发送 / 帧超时（RTU 侧）

- t1 内未发送新 I 帧 → 发 S 帧询问。
- t1 内未收到主站任何报文 → 链路异常。

t2：接收确认超时

- 收到 I 帧后 t2 内未发 S 帧 → 必须发 S 帧。
- 主站强制确认。

t3：空闲超时

- 链路空闲 t3 → 发 TESTFR_ACT 测试帧。

```text
工程经验：
  k = 12, w = 8   → 一般场景
  k = 8, w = 4    → 高速窄带
  k = 16, w = 12  → 大流量
```

## 公共地址与信息体地址

ASDU 中含两个地址：

```text
公共地址（Common Address）：2 字节，站址
信息体地址（Information Object Address, IOA）：3 字节
```

IOA 是测点号。注意 IEC 104 是 3 字节 IOA，IEC 101 在某些实现里也是 3 字节，但早期版本是 2 字节；需与主站协议栈对齐。

```text
IEC 104: IOA 3 字节
IEC 101: IOA 2/3 字节
```

实际 RTU 工程常见 3 字节 IOA。

## ASDU 字段详解

类型标识 Type ID（1 字节）：决定 ASDU 用途
VSQ Variable Structure Qualifier（1 字节）：

```text
bit 0..6：信息体数量
bit 7  ：SQ 位（1 = 顺序地址，0 = 离散地址）
```

COT Cause of Transmission（2 字节，低字节在前）：

```text
bit 0..5：原因码
bit 6  ：测试位
bit 7  ：肯定 / 否定确认位
bit 8..15：源地址（IEC 104 扩展）
```

常用 COT：

```text
1   = 突发（自发上报）
3   = 突发（自发）
5   = 请求 / 被请求
7   = 激活确认
8   = 停止激活
9   = 停止激活确认
20  = 总召唤响应
44  = 类型标识未知
45  = 类型标识未知
46  = ASDU 公共地址未知
47  = 信息体地址未知
```

## CP56Time2a 详解

7 字节结构：

```text
[字节 0]：毫秒低 8 位
[字节 1]：毫秒高 8 位（0..59999）
[字段 2]：分钟（0..59）
[字段 3]：小时（0..23）
[字段 4]：日（1..31）
[字段 5]：高 3 位 = 星期（0..7，0/7 = 未用）+ 低 5 位 = 月（1..12）
[字段 6]：年（0..99，相对 2000）
```

位 7（字节 0 的最高位）：

```text
0 = 有效时间
1 = IV（Invalid）无效
```

位 7（字节 1 的最高位）：

```text
0 = 正常
1 = 夏令时
```

位 7（字节 5 的最高位）：

```text
0 = 正常
```

工程实现：

```text
收到时钟同步 → 直接更新本地 RTC
解析 CP56Time2a → 转成 Unix 时间戳
发送带 CP56Time2a 的 ASDU → 编码本地 RTC
```

## 双点命令选择 / 执行 / 撤销

IEC 104 命令必须带选择（Select）→ 执行（Execute）两阶段。

```text
第 1 阶段：SE=1，命令内容（DO）
RTU：校验 → 激活确认（COT=7，SE=1）
第 2 阶段：SE=0，命令内容（DO）
RTU：执行 → 激活确认（COT=7，SE=0）
完成后：M_DP_NA_1 变位响应
```

撤销命令（COT=0x2D/0x2E）：

```text
主站发 SE=1 命令后 → 想取消 → 发 SE=1 + 命令码 = 撤销
RTU：返回停止激活（COT=8/9）
```

工程注意：

- 选择命令不直接动作，2 阶段流程可避免误操作。
- 执行前 RTU 应再次校验。
- 撤销超时主站应主动断开重连。

## 突发上传

突发上传（Spontaneous / Background Scan）：

```text
1. M_SP_NA_1 变位（突发）
3. M_ME_NC_1 越限（突发）
4. M_IT_NA_1 累积量增量（突发）
```

突发策略：

```text
方案 A：变位立即上传（k/w 限速）
方案 B：周期性扫描 + 变化量上传
方案 C：事件窗口合并上传（防突发风暴）
```

工程实现：

- RTU 内有事件队列（按 ASDU 类型分别）。
- 触发事件入队，后台线程按队列发送 I 帧。
- k 限速时排队等待 S 帧。

## 文件传输

IEC 104 支持文件传输（ASDU 122-127）：

```text
ASDU 122：文件就绪
ASDU 123：文件准备好
ASDU 124：文件段
ASDU 125：文件段确认
ASDU 126：文件传输结束
ASDU 127：文件传输结束确认
```

用途：

- 配置文件下载（ICD/SCD）。
- 录波文件上传。
- 故障报告。

工程实现：

- 主站发起文件召唤 → RTU 分段上传 → 校验 → 完成。
- 文件较大时分多次传输。

## 通用分类信息（GI）

ASDU 240-249 用于通用分类：

```text
ASDU 240：通用分类总召唤
ASDU 241：通用分类总召唤响应
ASDU 242：通用分类数据传输
ASDU 243：通用分类数据传输响应
ASDU 244：通用分类传输结束
ASDU 245：通用分类传输结束响应
ASDU 246：通用分类读写命令
ASDU 247：通用分类读写命令响应
ASDU 248：通用分类确认
ASDU 249：通用分类确认
```

GI 用于自定义数据扩展，是 IEC 104 最重要的扩展机制。配网 RTU、自定义测点常用 GI。

## 抓包排障

Wireshark 关键检查：

```text
1. TCP 连接是否建立
2. 启动字符 0x68 后是否有 STARTDT_ACT
3. STARTDT_CON 是否及时
4. N(S)/N(R) 序列号是否连续
5. S 帧间隔是否在 t2 内
6. TESTFR_ACT/CON 是否在 t3 空闲后发送
7. ASDU Type/COT/IOA 解析是否正确
```

## 现场常见故障

| 现象 | 优先检查 |
| --- | --- |
| STARTDT_CON 后总召唤无响应 | 总召唤 ASDU 公共地址错 |
| 总召唤响应数据不全 | ASDU 类型映射错或 IOA 偏移 |
| 突发数据堆积 | k/w 设置或 S 帧超时 |
| 命令激活确认但现场无动作 | 命令 SE 选择 → 执行顺序错 |
| 命令超时未确认 | RTU 端校验失败 |
| t1 报警链路断 | 实际网络延迟 |
| 累积量精度漂移 | 编码 / 解码 byte order |
| 文件传输失败 | 分段名/检测机制 |
| 历史数据不连续 | 突发事件队列溢出 |

## 深度检查清单

- TCP 端口 2404 已开（RTU 端）。
- 启动字符 0x68 + 长度字段解析正确。
- I/S/U 三种 APDU 格式状态机实现完整。
- k/w/t1/t2/t3 与主站协商一致。
- N(S)/N(R) 字节序正确（低字节在前）。
- 公共地址、IOA、VSQ、SQ 解析正确。
- ASDU 类型与 COT 处理完整。
- CP56Time2a 编解码正确（含夏令时和无效标志）。
- 双点命令选择 → 执行 → 撤销流程完整。
- 突发上传限速策略合理。
- 文件传输 / GI 扩展按需实现。
- 多主站连接管理（如支持）。
- 异常重连机制（含 TCP Keepalive）。
