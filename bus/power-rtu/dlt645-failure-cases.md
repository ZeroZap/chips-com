# DL/T 645 产线死机案例库

## 目标

把产线常见的 DL/T 645 电表通信失败、地址配置错、密码错、块读协议错、BCD 解码错等写成案例库。

## 案例 1：表地址未配置

### 现象

主站发广播读，所有表无响应。

### 排查

```text
表地址：99 99 99 99 99 99（出厂默认）
原因：表地址未配置。
```

### 修复

用抄表器配置表地址为真实地址。

### 复盘

```text
1. 出厂表地址 = 99 99 99 99 99 99（未配置）
2. 多表广播会导致所有表同时响应
3. 部署前必须配置表地址
4. 上电后第一件事是配置地址
```

## 案例 2：表地址配置错

### 现象

主站读表，RTU 显示"无响应"，实际表存在。

### 排查

```text
表实际地址：12 34 56 78 90 12
主站读：12 34 56 78 90 13（错 1 位）
```

### 修复

主站地址配置纠正。

### 复盘

```text
1. 表地址必须精确一致
2. 调试时抄表器先确认表地址
3. 主站配置表地址文档必须维护
4. 部分厂家地址有不可见字符，注意 BCD 编码
```

## 案例 3：偶校验错

### 现象

主站串口 8N1，电表 8E1。

### 排查

```text
抓字节：错位
原因：偶校验位错
```

### 修复

主站串口参数改 8E1。

### 复盘

```text
1. DL/T 645 通常 8E1
2. 主站 / RTU 串口参数必须一致
3. 调试工具与设备参数一致
```

## 案例 4：A/B 反接

### 现象

完全不通信。

### 排查

```text
差分电压异常
原因：A/B 反接
```

### 修复

### 复盘

```text
1. RS485 A/B 命名可能不周厂
2. 不通信时优先交换 A/B
3. 多个表并接时优先单表调试
```

## 案例 5：DE 等待 TXE 截断最后字节

### 现象

主站发命令，RTU 接收最后 1 字节错。

### 修复

等 TC 而不是 TXE。

### 复盘

```text
1. DL/T 645 与 Modbus RTU 的 RS485 物理层共享
2. DE 必须等 TC
3. 与 Modbus RTU 同样的问题
```

## 案例 6：DI 字节序错

### 现象

主站读 DI=00000000 总电能，RTU 当作 DI=00000001 上一日总电能。

### 抓包

```text
主站 → DI = 00 00 00 00
RTU 解析：DI = 00 00 00 01    # 字节序错
```

### 定位

RTU DI 解析字节序错。

### 修复

```c
/* RTU 端正确解析 */
di = (buf[0] << 24) | (buf[1] << 16) | (buf[2] << 8) | buf[3];
```

### 复盘

```text
1. DI 4 字节是高字节在前
2. 不同协议字节序不同
3. 测试用例必须验证 DI 边界
```

## 案例 7：BCD 解码错

### 现象

主站解析电能 100.32 kWh，实际数据是 100.32 kWh。

### 抓包

```text
RTU DATA = 00 01 00 32    # BCD
主站解析：0x00010032 = 65650 / 100 = 656.50（错）
```

### 定位

主站没做 BCD 解码，直接当二进制。

### 修复

```c
/* BCD 解码 */
uint32_t bcd_decode(uint8_t *data, int len) {
    uint32_t val = 0;
    for (int i = 0; i < len; i++) {
        val = val * 100 + ((data[i] >> 4) * 10) + (data[i] & 0x0F);
    }
    return val;
}
```

### 复盘

```text
1. DL/T 645 数据全部 BCD
2. 二进制解析会得到错误数据
3. 必须 BCD 解码
4. 测试用例必须验证 BCD 边界
```

## 案例 8：写数据无密码

### 现象

主站发写数据命令 RTU 不响应。

### 抓包

```text
主站：68 ... 06 04 [DI] [DATA]    # 写数据
RTU：68 ... C6 ERR=06    # 密码错
```

### 定位

主站没先修改密码流程。

### 修复

```text
1. 先发 0x08 修改密码
3. 后发 0x06 写数据
```

### 复盘

```text
1. DL/T 645 写数据前必须验证密码
2. 密码权限必须满足目标操作
3. 测试用例必须覆盖写密码流程
```

## 案例 9：密码错

### 现象

主站发修改密码 RTU 不响应。

### 排查

```text
主站密码：12345678
RTU 默认密码：00000000
```

### 修复

用 RTU 默认密码 + 新密码流程。

### 复盘

```text
1. 各家电表默认密码可能不同
2. 部署前必须确认默认密码
3. 密码修改流程不能跳过
```

## 案例 10：块读不完整

### 现象

主站发 0x01 读 DI=0201FF00（所有瞬时量），但只读到部分。

### 排查

```text
多帧协议：DI D0 最高位 = 1 标识后续帧
主站：未实现 0x02 后续读
```

### 修复

主站实现 0x02 后续读。

### 复盘

```text
1. 块读协议必须支持 0x02 后续读
2. 一直读到 D0 最高位 = 0
3. 测试用例必须覆盖多帧协议
```

## 案例 11：ESAM 错

### 现象

主站发远程购电命令 RTU 不响应。

### 排查

```text
ERR = 0x40 ESAM 错
```

### 修复

检查 ESAM 模块、密钥、ESAM 指令。

### 复盘

```text
1. 远程购电需要 ESAM
2. ESAM 模块故障 / 密钥错 → ERR 0x40
3. 部署前必须确认 ESAM 集成
```

## 案例 12：红外不通

### 现象

手持抄表器读不到表。

### 排查

```text
距离 > 30 cm 或角度 > 30°
```

### 修复

手持抄表器对准红外口，距离 < 10 cm。

### 复盘

```text
1. 红外通信距离 / 角度限制
2. 强光环境红外受干扰
3. 38 kHz 调制必须正确
```

### 现象

主站发读命令 RTU 不响应。

### 排查

```text
主站 9600 baud，电表 2400 baud
```

### 修复

### 复盘

```text
1. 部分电表支持自适应
2. 部分需要手动按电表速率
3. 调试时多试几个波特率
```

## 案例 14：广播误用

### 现象

主站发广播写，所有表都被改。

### 修复

写操作不能用广播地址。

### 复盘

```text
1. DL/T 645 广播地址 = AA AA AA AA AA AA
2. 广播只读不写（部分实现允许写）
3. 写操作必须用具体地址
4. 远程控闸等敏感操作不能广播
```

## 案例 15：事件记录丢失

### 现象

主站读事件记录（DI=04000001）但读不到。

### 排查

```text
ERR = 0x02 请求数据不存在
原因：事件未发生
```

### 修复

触发事件（掉电 / 编程）后重读。

### 复盘

```text
1. 事件记录 DI 实际事件触发才存在
2. 测试用例必须用真实事件
3. 仿真事件（编程事件最简单）
```

## 案例 16：冻结量时间错

### 现象

主站读冻结量（DI=03010000）但时间错。

### 排查

```text
冻结时间点不对
原因：日冻结 0:00 切换
```

### 修复


## 案例 17：32-bit 数据字节序错

### 现象

主站读 32-bit 数据（如电压电流），数值错。

### 抓包

```text
RTU DATA = 12 34 56 78
主站解析：0x12345678 = 305419896（错）
```

### 定位

32-bit 跨两个寄存器的字节序未确认。

### 修复

按厂家手册确认字节序（ABCD / CDAB / BADC / DCBA）。

### 复盘

```text
1. 32-bit 数据有 4 种字节序
2. 不同厂家不同
3. 必须实测确认
```

## 案例 18：DI 块码不识别

### 现象

主站读 DI=0201FF00（所有瞬时量），但 RTU 不支持。

### 修复

主站按单 DI 读，不用块码。

### 复盘

```text
1. 部分老表不支持块码
2. 兼容性策略
4. 主站实现"部分读"备份
```

## 案例 19：CRC 累加范围错

### 现象

主站计算 CS 错。

### 抓包

```text
主站 CS 计算 = 0x68 + 0xAA*6 + 0x68 + 0x01 + 0x04 + 0x00*4 + 0x16 = 0xXXXX
```

### 定位

主站 CS 计算包含了 0x16（结束符）。

### 修复

CS 计算范围：从 0x68 到 DATA 末尾（不含 0x16）。

### 复盘

```text
1. DL/T 645 CS 计算范围不含 0x16
2. 不含 0x68 启动字符之后的 LEN/控制吗？不，含。
3. 必须按协议规范
```

## 案例 20：多表冲突

### 现象

主站分时轮询多表，偶发冲突。

### 排查

```text
主站发读后未等响应（未等 3.5 字符时间）
下一个表发响应
```

### 修复

主站严格分时轮询：

```c
send_read_table_1();
wait_response();
delay_3.5_char();
send_read_table_2();
```

### 复盘

```text
1. RS485 半双工必须错开时序
2. 多表轮询必须严格分时
3. 工程实践：等待 3.5 字符时间
```
