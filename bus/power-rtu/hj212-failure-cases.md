# HJ 212 产线死机案例库

## 目标

把产线常见的 HJ 212 环保联网通信失败、TCP 连通性、因子字典、心跳超时、省级平台差异等写成案例库。

## 案例 1：TCP 端口错

### 现象

RTU 连不上省级平台。

### 排查

```text
主站端口：8000（江苏）
RTU 端口：5000（默认）
```

### 修复

修改 RTU 端口 = 8000。

### 复盘

```text
1. 不同省份端口不同
2. 部署前必须与省级平台确认
3. 8000 / 5000 / 9501 是常见端口
```

## 案例 2：MN 设备编号未注册

### 现象

RTU 连接成功，但所有上报平台都不入库。

### 排查

```text
RTU MN = 1234567890123
省级平台未注册
```

### 修复

在省级平台注册 MN。

### 复盘

```text
1. MN 是设备唯一标识
2. 必须先到省级平台注册
3. 重新下发后才能正常上报
```

## 案例 3：PW 密码错

### 现象

RTU 心跳应答正常，但实时数据不被接收。

### 排查

```text
RTU PW = 123456
省级平台 PW = 654321（错配）
```

### 修复

主站 PW 与省级一致。

### 复盘

```text
1. PW 是 6 位数字
2. 主站 / 省级必须一致
3. 注册时分配
```

## 案例 4：心跳超时

### 现象

RTU 心跳 3 分钟一次，但平台报"链路断"。

### 排查

```text
平台要求 1 分钟一次
RTU 3 分钟一次
```

### 修复

修改 RTU 心跳周期 = 1 分钟。

### 复盘

```text
1. 不同平台心跳要求不同
2. 部署前必须确认心跳周期
3. 心跳超时通常 3 倍心跳周期
```

## 案例 5：## 标识未识别

### 现象

RTU 发数据平台完全收不到。

### 排查

```text
RTU 发 ##QN=......
（实际发 \n#QN=... ）  # 误加 \n
```

### 定位

RTU 软件 bug，开头多了 \n。

### 修复

去掉 \n。

### 复盘

```text
1. ## 是固定起始符
2. 多余字符导致报文错
3. 测试用例必须验证报文格式
```

## 案例 6：CP=&& 数据起始错

### 现象

RTU 数据上报但平台解析错。

### 排查

```text
RTU 发：&ST=22&CN=2011...
（实际遗漏 CP=&&）
```

### 定位

RTU 软件漏发 CP=&&。

### 修复

补全 CP=&&。

### 复盘

```text
1. CP=&& 是固定字段
2. 缺失会导致解析失败
3. 测试用例必须验证 Header 字段
```

## 案例 7：因子字典不匹配

### 现象

RTU 上报 a21026 流量，平台不识别。

### 排查

```text
省级平台字典：w21026（不同省份编码）
```

### 修复

修改 RTU 因子编码为省级字典。

### 复盘

```text
1. 不同省份因子编码可能不同
2. 部署前必须确认字典
3. 统一字典标准
```

## 案例 8：实时数据未入库

### 现象

RTU 上报 CN=2011 实时数据，平台不接收。

### 排查

```text
平台要求：CN=2011
RTU 发：CN=2011（正确）
原因：Flag-N 字段 = B（异常），平台误判
```

### 修复

修改 RTU 数据状态 Flag-N = N。

### 复盘

```text
1. Flag-N 字段影响入库
2. N 正常 / B 异常 / F 超标
3. 部分平台对 B / F 处理不同
```

## 案例 9：分钟数据堆积

### 现象

RTU 分钟数据堆积，每分钟 50 条。

### 排查

```text
部分省份要求：每 5 分钟 1 次
RTU 配置：每分钟 1 次
```

### 修复

修改 RTU 分钟频率 = 5 分钟。

### 复盘

```text
1. 分钟数据频率各省不同
2. 部署前必须确认频率要求
3. 频率过高导致 SIM 卡流量费高
```

## 案例 10：CRC 校验失败

### 现象

RTU 上报平台报"CRC 错"。

### 排查

```text
RTU CRC 算法：CRC-16/MODBUS
平台 CRC 算法：CRC-16/XMODEM（错配）
```

### 修复

主站 / RTU 统一 CRC 算法（HJ 212 标准 CRC-16/MODBUS）。

### 复盘

```text
1. HJ 212 CRC 是 CRC-16/MODBUS
2. 但 HJ 212 CRC 不是必填项
3. 部分省级要求必须 CRC
```

## 案例 11：超标数据漏报

### 现象

设备测量值超国标，平台未收到超标报告。

### 排查

```text
RTU：测量值超阈值，但未触发超标上报
原因：超标阈值未配置
```

### 修复

配置超标阈值。

### 复盘

```text
1. HJ 212 超标数据必须明确阈值
2. 阈值由现场工艺确定
3. 测试用例必须触发超标事件
```

## 案例 12：命令无应答

### 现象

平台发命令 CN=3021，RTU 不应答。

### 排查

```text
RTU 现场：CN=3021 命令未实现
```

### 修复

RTU 实现命令处理（执行 / 应答）。

### 复盘

```text
1. 平台下发的命令 RTU 必须实现
2. 部署前必须确认命令支持
3. 测试用例必须验证所有命令
```

### 现象

省级加密：DES
RTU 未加密
```

### 修复

```

## 案例 14：MN 临时编码误用

### 现象

RTU 上报平台入库但标识为"临时设备"。

### 排查

```text
RTU Flag bit 2 = 1（临时编码）
```

### 修复

修改 RTU Flag bit 2 = 0。

### 复盘

```text
1. Flag bit 2 = 临时编码标志
2. 部分平台对临时设备处理不同
3. 长期部署必须 MN 已注册 + Flag 正确
```

## 案例 15：数据时间错

### 现象

RTU 上报数据时间都错。

### 排查

```text
RTU 本地 RTC：2024-09-25 12:00:00
平台解析：2024-09-25 20:00:00（UTC vs local）
```

### 修复

主站 / RTU 约定时区处理。

### 复盘

```text
1. HJ 212 QN 时间是本地时间还是 UTC 需约定
3. RTU 必须按本地时间
```

## 案例 16：SIM 卡流量耗尽

### 现象

4G RTU 失联。

### 排查

```text
SIM 卡流量耗尽
```

### 修复

更换 SIM 卡 + 配置流量套餐。

### 复盘

```text
1. 4G RTU 必须监控流量
2. 部分平台心跳 + 数据流量大
3. 流量套餐需匹配上报频率
```

## 案例 17：VPN 断开

### 现象

RTU 在 VPN 隧道内，部分省份要求 VPN 连接。

### 排查

```text
RTU VPN 配置丢失
```

### 修复

重新配置 VPN。

### 复盘

```text
1. 部分省份要求 VPN / 专网
2. VPN 配置必须稳定
3. 工程实践：VPN 客户端自动重连
```

## 案例 18：离线数据补传失败

### 现象

TCP 恢复后离线数据未补传。

### 排查

```text
RTU 未实现离线数据缓存
```

### 修复

RTU 实现离线数据缓存 + 补传机制。

### 复盘

```text
1. HJ 212 离线数据必须缓存
2. TCP 恢复后批量补传
3. 补传机制是工程要求
```

## 案例 19：心跳应答超时

### 现象

RTU 发 CN=1000 心跳，平台未及时应答 CN=1001。

### 排查

```text
RTU 心跳超时设置：10s
平台应答延迟：15s
```

### 修复

调整心跳超时 = 20s。

### 复盘

```text
1. 心跳超时必须宽松
2. 平台应答延迟可能较大
3. 工程实践：心跳超时 = 3 倍心跳周期
```

## 案例 20：多中心站连接冲突

### 现象

RTU 连接两个中心站（省级 + 地市级），冲突。

### 排查

```text
RTU 单 TCP 连接
两个平台争抢连接
```

### 修复

```text
1. RTU 多 TCP 连接
3. 或前置机代理多平台
```

### 复盘

```text
1. HJ 212 部分支持多平台
2. 多平台需 RTU 实现支持
3. 工程实践：前置机代理多平台
```
