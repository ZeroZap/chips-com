# IEC 60870-5-104 Practical Guide

## 目标

本文用于把 IEC 104 工程链路调通：主站 / RTU 的 TCP 建立、APCI 帧收发、ASDU 解析、总召唤与时钟同步、命令下行和测试联调。

## TCP 链路

```text
主站 IP:Port  -----TCP----->  RTU IP:2404
```

常见做法：

- RTU 作 server，监听 2404。
- 主站作 client，主动连接。
- 一个 RTU 通常只允许 1 个主站连接；多主站需在前置机侧做代理。

防火墙和 NAT 注意事项：

- 2404 不能映射成临时端口范围。
- 双向连通性确认（RTU 多在 NAT 后）。
- 长连接保活（TCP Keepalive + IEC 104 t1/t2/t3 协议层）。

## 启动流程

主站侧：

```text
1. 主动 TCP 连接 RTU:2404
3. 发 STARTDT_ACT（U 格式）
4. 等 STARTDT_CON
5. 发 C_IC_NA_1 总召唤命令（I 格式）
6. 收总召唤响应（多个 ASDU）
7. 周期性发 C_CS_NA_1 时钟同步
```

常见错误：

- 没发 STARTDT_ACT 就发 I 帧，RTU 直接丢弃。
- 总召唤周期过短，I 帧堆积。
- t1 超时没设好，主站误判链路断。

## 报文示例（十六进制）

STARTDT_ACT（U 格式）：

```text
68 04 07 00 00 00
```

STARTDT_CON：

```text
68 04 0B 00 00 00
```

总召唤命令（C_IC_NA_1，公共地址 1，QOI=1 总召唤）：

```text
68 0E 00 00 00 00
       64 01 06 00 01
       00 01 00 00 00
```

字段解释：

```text
68      : 启动字符
0E      : APDU 长度 = 14 字节
00 00   : 发送序号 N(S) = 0
00 00   : 接收序号 N(R) = 0
64      : 类型标识 = 100 = C_IC_NA_1
01      : VSQ = 1
06      : COT = 6 激活
00 01   : 公共地址 = 1
00      : QOI = 1（总召唤，非停止）
00 00 00 : 0（信息体地址起点）
```

总召唤响应示例：单点信息 M_SP_NA_1。

```text
68 14 ...
       01 01 07 00 01 00
       00 01 00 00
       01 03
```

含义：

```text
类型 01 = M_SP_NA_1 单点
VSQ 01 = 1 个对象
COT 07 = 激活确认
公共 01 00
信息体地址 00 01 = 点号 1
值 01 = 合，品质 03 = 良好
```

## 时钟同步 C_CS_NA_1

```text
68 12 ...
       67 01 06 00 01 00
       00 01 00
       F1 0A 02 14 09 06 1B
```

CP56Time2a 字段（7 字节）：

```text
F1 0A   : 毫秒 = 0x0AF1 = 2801
02      : 分 = 2
14      : 时 = 14
09      : 日 = 9
06      : 星期 6（星期日 = 7，不关心 = 0）+ 月 6
1B      : 年 = 27（2000 + 27 = 2027）
```

## 命令处理流程（双命令）：

```text
1. 主站：C_DC_NA_1 双点命令，SE=1（选择），分=01
2. RTU：C_DC_NA_1 激活确认，SE=1
3. 主站：C_DC_NA_1 双点命令，SE=0（执行），分=10
4. RTU：C_DC_NA_1 激活确认，SE=0
5. RTU：M_DP_NA_1 双点变位响应，分=10
```

错误响应：

```text
COT = 0x2D（45）取消选择 / 0x2E（46）取消激活
```

## 参数协商

主站侧应与 RTU 协商一致的参数：

```text
k = 12
w = 8
t1 = 15 s
t2 = 10 s
t3 = 20 s
t0 = 10 s
```

工程常见值：

- 高实时性：t1 = 5 s, t2 = 3 s。
- 低带宽长链路：t1 = 30 s, t2 = 20 s。

## 调试工具

- Wireshark：IEC 60870-5-104 dissector。
- 主站模拟：openMUC、openSCD、IEC 104 主站测试工具。
- RTU 模拟：lib60870、IEC 104 Slave Simulator。
- 串口抓包工具：WireShark + IEC 60870-5-104 over TCP。

Wireshark 解码示例：

```text
应用层：IEC 60870-5-104
  APCI: Type=I, N(S)=5, N(R)=8
  ASDU: M_ME_NC_1 (13), COT=3 (突发), Addr=1, IOA=10
    Value: 230.5
```

## 调试步骤

1. 用 Wireshark 抓 TCP:2404，确认 0x68 启动字符和长度字段。
2. 确认 STARTDT_ACT / CON 完成。
3. 发总召唤 C_IC_NA_1，确认各 ASDU 类型和 COT。
4. 触发变位事件，确认 M_SP_TB_1 / M_DP_TB_1 上行。
5. 启动 t1/t2/t3 监控，确认 S 帧间隔。
6. 命令下行：单点命令选择 + 执行，确认激活确认。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 完全无数据 | TCP 连通性、防火墙、2404 端口 |
| 收到 STARTDT_CON 后无总召唤 | 总召唤 ASDU 公共地址错 |
| 总召唤响应不全 | ASDU 类型 / COT 字段解析错 |
| t1 报警链路断 | RTU 侧网络延迟或拥塞 |
| 命令激活确认但执行超时 | 二次确认（SE）字段错误 |
| 变位事件漏报 | 突发模式 + 缓存溢出 |

## 实战检查清单

- TCP 端口 2404 监听（RTU 侧）。
- 主站 / RTU 链路建立正常（STARTDT_ACT / CON）。
- 总召唤正常返回所有测点。
- 时钟同步周期稳定。
- 突发上传按变位 / 越限触发。
- 命令带选择 → 执行流程正确。
- k / w / t1 / t2 / t3 与主站一致。
- Wireshark 解码报文与设计一致。
