## 一、协议层分解（核心答案）

J1939 不是单个协议，而是 **SAE 维护的协议族**。按 OSI 分层展开：

```text
┌──────────────────────────────────────────────────────────────┐
│ L7 应用层    J1939-71  车辆应用层（PGN/SPN 定义、EEC1 等）   │
│              J1939-73  诊断应用层（DM1/DM2/DM14 等）         │
├──────────────────────────────────────────────────────────────┤
│ L6 表示层    （无独立标准；SAE J1939-71 的 SPN 定标承担此职能）│
├──────────────────────────────────────────────────────────────┤
│ L5 会话层    （无独立标准）                                   │
├──────────────────────────────────────────────────────────────┤
│ L4 传输层    J1939-21 内含 TP：TP.CM / TP.DT               │
│               BAM（广播） / RTS-CTS（点对点）                 │
│               多包上限 255 包 × 7 B = 1785 B                │
├──────────────────────────────────────────────────────────────┤
│ L3 网络层    J1939-31  网络布局与路由（网关/桥接）           │
├──────────────────────────────────────────────────────────────┤
│ L2 数据链路  J1939-21  29-bit ID 编码、PGN、PDU1/PDU2、TP   │
│              J1939-22  J1939 over CAN FD（数据链路）          │
│              J1939-84  越野重型车 OBD 合规（附加约束）       │
├──────────────────────────────────────────────────────────────┤
│ L1 物理层    J1939-11  250 kbit/s 双绞 120Ω                 │
│              J1939-14  500 kbit/s（工程机械变体）            │
│              J1939-15  简化物理层（轻型车/乘用车）           │
│              J1939-17  CAN FD 物理层                        │
├──────────────────────────────────────────────────────────────┤
│ 辅助标准     J1939-13  诊断连接器（13 针 / DB9）             │
│              J1939-81  网络管理（NAME、地址声明）            │
│              J1939-91A 网络安全建议                          │
│              J1939-01/-02 体系总则 / 卡车客车合规            │
│              J1939-DA  参数数据库（Excel，非 SAE 正式编号）  │
└──────────────────────────────────────────────────────────────┘
```

**层间依赖**：

```text
J1939-71 / -73 (应用+诊断)
        ↓
J1939-21 (数据链路 + 传输)
        ↓
CAN 2.0B 控制器
        ↓
J1939-11 / -14 / -15 (物理)
```

### 典型商用车协议栈选型

| 层 | 常用选型 |
| --- | --- |
| 物理层 | 非屏蔽双绞线，250 kbit/s 或 500 kbit/s |
| 数据链路层 | J1939-21 |
| 网络管理 | OSEK 网络管理 或 AUTOSAR 网络管理；也可用 J1939-81 的地址声明 |
| 诊断 | J1939-73 的 DM 报文，或 **DM1 报文 + UDS 组合** |
| 应用层 | J1939-71（现由 J1939-DA 承载参数定义） |

> **诊断双轨制**：法规强制要求商用车必须支持 **DM1**（仪表故障灯由 DM1 控制点亮），UDS 是厂家自定义的增强诊断体系，两者共存而非替代关系。

## 二、标准号速查（按层）

| 标准号 | 层 | 作用 |
| --- | --- | --- |
| **SAE J1939-21** | 数据链路 | **核心标准**：29-bit ID、PGN 构成、TP 多包传输（BAM / RTS-CTS） |
| SAE J1939-22 | 数据链路 | J1939 跑在 CAN FD 上的数据链路层 |
| SAE J1939-17 | 物理 | CAN FD 物理层 |
| SAE J1939-31 | 网络层 | 网络布局与路由 |
| SAE J1939-81 | 网络管理 | NAME 字段、地址声明、Commanded Address |
| SAE J1939-71 | 应用层 | 车辆应用层（PGN / SPN 定义） |
| SAE J1939-73 | 应用层（诊断） | DM1 / DM2 等诊断报文格式 |
| SAE J1939-84 | 合规 | 越野重型车 OBD 合规（**不是**一致性测试规范） |
| SAE J1939-01 / -02 | 合规 | J1939 体系总则 / 卡车客车合规性 |
| SAE J1939-11 | 物理 | 250 kbit/s 物理层（双绞 120Ω） |
| SAE J1939-14 | 物理 | 500 kbit/s 物理层（部分工程机械） |
| SAE J1939-15 | 物理 | 简化物理层（轻型车 / 乘用车） |
| SAE J2284-1 ~ -4 | 物理 | 北美 CAN 物理层 |
| SAE J1939-13 | 连接器 | 车载诊断连接器（DB9 / 13 针） |
| SAE J1939-91A | 安全 | 车载网络接口安全建议 |

**物理层关键指标**（J1939-11）：

- 介质：屏蔽双绞线
- 速率：250 kbit/s（J1939-14 为 500 kbit/s）
- 同一网络最大子系统数：**30 个**
- 最大传输线长度：**40 m**

## 三、29-bit CAN ID 字段

J1939 使用 **CAN 2.0B 扩展帧**（29-bit ID）。标准帧在 J1939 网络中只能作为"专用消息"按特定方式运行，**J1939 设备必须使用扩展帧**。

```text
Priority(3) | EDP(1) | DP(1) | PF(8) | PS(8) | SA(8)
```

| 字段 | 位宽 | 说明 |
| --- | --- | --- |
| P（优先级） | 3 | 仲裁用，0 最高、7 最低。仅发送时有效，**接收端必须忽略**。控制类报文默认 **3**，其他报文默认 **6**。OEM 可重新编程 |
| EDP（扩展数据页） | 1 | 2006-06 修订版起定义为 EDP，此前为保留位 R。传送时所有 J1939 报文置 **0** |
| DP（数据页） | 1 | 选择 PGN 辅助页。页 0 的 PGN 全部分配完后才用页 1。EDP=DP=11 时表示 **ISO 15765-3** 报文（ID 构成与 J1939 不同，J1939 规范未描述） |
| PF（PDU 格式） | 8 | 决定 PDU1 / PDU2，是 PGN 的组成部分 |
| PS（PDU 特定域） | 8 | 含义由 PF 决定：PF<240 → **目标地址 DA**；PF≥240 → **组扩展 GE** |
| SA（源地址） | 8 | 发送设备地址，全网唯一。见 SAE J1939-81 的地址分配表 |

### EDP / DP 数据页对照表

| EDP | DP | 描述 |
| --- | --- | --- |
| 0 | 0 | SAE J1939 与 ISO 11783 |
| 0 | 1 | SAE J1939 NMEA 2000 |
| 1 | 0 | SAE J1939 保留 |
| 1 | 1 | ISO 11992 诊断（无 J1939 布局） |

> SAE J1939 中实际只使用前 3 种组合。

### RTR 与保留位

- **RTR 在 J1939 中始终为显性 0**，远程帧（逻辑 1）不适用于 J1939。
- 控制段的 r1 / r0 为保留位，默认显性位。
- DLC 段、CRC 段、ACK 段、帧结束与 CAN 2.0B 完全一致（Classic CAN 数据场 8 字节；CAN FD 最多 64 字节）。

## 四、PDU 与 PGN

### PDU 组成

协议数据单元（PDU）由七部分组成：

```text
优先级 | EDP | DP | PF | PS（DA 或 GE） | SA | 数据场
```

PDU 被封装在一个或多个 CAN 数据帧中传送，**每个 CAN 数据帧只能包含一个 PDU**。

### PGN 的构成

PGN（Parameter Group Number）共 **24 bit**，是 CAN 29-bit ID 的一个子集，不是 ID 的全部：

```text
PGN = 6 个 0 | EDP(1) | DP(1) | PF(8) | PS(8)
```

计算规则：

| PDU 类型 | PF 范围 | PS 含义 | PGN 计算 | 寻址 |
| --- | --- | --- | --- | --- |
| **PDU1** | 0 ~ 239 | 目标地址 DA | `EDP \| DP \| PF \| 00` | 可点对点，也可全局（DA=255） |
| **PDU2** | 240 ~ 255 | 组扩展 GE | `EDP \| DP \| PF \| GE` | **只能广播** |

**PGN 全局类 vs 特定类**：

- **全局 PGN**：识别广播给所有设备的参数组 —— PF ≥ 240，PS 为组扩展。
- **特定 PGN**：用于点对点发送 —— PF ≤ 239，PS 置 0。

无论哪一类，PGN 都由 PF、PS、DP、EDP 共同识别。

### PGN 容量计算

```text
PDU1：每数据页 240 个
PDU2：每数据页 16 × 256 = 4096 个
每数据页共 240 + 4096 = 4336 个
两个数据页（DP=0 / DP=1）：4336 × 2 = 8672 个 PGN
```

### 两条硬约束

1. **PDU1 数量有限**，主要用于必须指定目标地址的 PGN；大部分 PGN 定义在 PDU2 段。
2. **更新速率 < 100 ms 的报文不允许多包发送**（保证实时性）；> 100 ms 的才允许走 TP。

### ID 解析示例

**例 1 — PDU1：`0x0C040B00`**

| 字段 | 值 | 含义 |
| --- | --- | --- |
| Priority | 3 | 控制类默认优先级 |
| EDP / DP | 0 / 0 | 第 0 页 |
| PF | 0x04 | < 240 → **PDU1** |
| PS | 0x0B | 目标地址 = EBS（商用车制动控制器） |
| SA | 0x00 | EMS（发动机控制器） |
| **PGN** | **0x000400 = 1024** | **XBR 制动报文** |

解读：发动机控制器发给制动控制器的制动相关请求。

**例 2 — PDU2：`0x18FE414A`**

| 字段 | 值 | 含义 |
| --- | --- | --- |
| Priority | 6 | 普通报文默认优先级 |
| PF | 0xFE | ≥ 240 → **PDU2** |
| PS | 0x41 | 组扩展 GE |
| SA | 0x4A | Tbox |
| **PGN** | **0x00FE41 = 65089** | **LCMD 灯光控制报文** |

**例 3 — 逐位拆解 `0x18FECA17`**

```text
字节 1 = 0x18 = 0001 1000 → Priority=3(110), EDP=0, DP=0
字节 2 = 0xFE            → PF=254 > 240 → PDU2
字节 3 = 0xCA            → GE=0xCA（PF>240，GE 取正常值）
字节 4 = 0x17            → SA=0x17（发送节点）
⇒ PGN = 0x00FECA = 65226 = DM1 诊断报文
```

## 五、五种报文类型

J1939 定义了 **5 种报文类型**，由其分配的 PGN 识别：

| 类型 | 说明 | PDU 格式 | 典型 PGN |
| --- | --- | --- | --- |
| **命令 Command** | 从某源地址命令特定或全局目的地执行特定动作（传动控制、地址请求、扭矩/速度控制等） | PDU1、PDU2 均可 | 65341 (RTS/CTS 等) |
| **请求 Request** | 请求全局或特定目标地址发送信息，最典型是"请求 PGN" | PDU1 / PDU2 | **59904 (0xEA00)** |
| **广播/响应** | 设备主动广播或对命令/请求的响应。**总线上大多数数据交换属此类**（ECU 周期广播参数） | PDU1 / PDU2 | EEC1 = 61444 等 |
| **确认 Ack** | 见下方说明 | PDU1 | 59392 (ACK) |
| **组功能 Group Function** | 一组特殊功能（专用功能、网络管理功能、多组传输功能等），每个组功能由其 PGN 识别 | — | 见 SAE J1939-21 |

### 请求报文的响应规则

- **针对特定目标地址的请求**：目标地址必须响应。若不支持该 PGN，**必须发出 NACK** 表明不支持。
- **全局请求**：某节点不支持某 PGN 时，**不能发 NACK**（否则多节点响应会冲突）。
- 部分 PGN 是多包的，**单帧请求的响应可能有多个 CAN 数据帧**。

### 确认（Acknowledgment）报文的四种控制字节

| 控制字节 | 含义 |
| --- | --- |
| 0 | 肯定确认（ACK） |
| 1 | 否定确认（NACK） |
| 2 | 拒绝访问 |
| 3 | 无法响应 |

确认有两种形式：

1. **帧内确认** —— CAN 协议层规定，由"消息已被至少一个节点接收"构成。若未出现 CAN 出错帧，表示所有在线设备都正确收到了该消息。
2. **应用层确认** —— 对特定命令/请求的普通广播或 ACK / NACK 响应，即上表。

## 六、PGN 与 SPN

### PGN

PGN 是 J1939 标准中的**唯一帧标识符**，用于引用一组参数。每个 PGN 包含：

- 8 字节 CAN 数据字段中的参数分配（字节排布）
- 重复率（传输周期）
- 优先级

### SPN

SPN（Suspect Parameter Number，怀疑参数编号）标识参数组中的单个参数，在通信 DBC 中**一个信号 = 一个 SPN**。

| 属性 | 值 |
| --- | --- |
| 位宽 | **19 bit** |
| 范围 | 0 ~ 524287 |
| 专有保留区 | **520192 ~ 524287** |
| 字节序 | 始终 **LSB → MSB**（Intel / 小端） |
| 复现 | 同一 SPN 可存在于多个 PGN 中 |

SPN 描述参数时提供：数据长度、规模（scaling）、数据类型、单位、分辨率（resolution）、偏移（offset）、范围、参考标签。

标准将 SPN 描述定义为 **SLOT**（Scaling, Limit, Offset and Transfer Function —— 比例、界限、偏移和转换函数）。

> **重要**：SPN 有**两处用途** —— ① 在通信 DBC 中代表信号；② 在诊断中代表**故障发生的位置**（与 FMI 共同构成 DTC）。

### 多字节参数的字节序

针对出现在 CAN 数据帧数据域中的多字节参数，**有效字节优先存放在最低字节**：

```text
2 字节参数放在字节 7、字节 8 → LSB 放字节 7，MSB 放字节 8
```

### 特殊取值

| 数据字节值 | 含义 |
| --- | --- |
| **0xFF (255)** | N/A —— 该应用不支持此参数（不代表真实值） |
| **0xFE (254)** | 错误（Error） |

### SPN 解析实例（SPN 190 发动机转速）

1. 由 CAN ID 推出 PGN：`0x0CF00401` → PGN = **61444（EEC1）**。
2. 查 SAE J1939-71 / J1939-DA：EEC1 含 7 个 SPN，其中 **SPN 190 = 发动机转速**，占字节 4~5。
3. 按 SLOT 计算工程值：

```text
物理值 = 原始值 × 分辨率 + 偏移
```

4. 数据字节为 0xFF/255 时表示该应用不支持此参数，不可当真实值使用。

> **实践提醒**：DBC 中的分辨率与 J1939-71 文档可能略有差异，通常是整车厂对该参数做了私有调整。其余属性（长度、偏移、单位）一般与文档一致。

### 数据定义规范

定义自定义 PGN 时的参数规范示例（以逆变器为例，PGN 65284）：

| 参数 | 长度 | 分辨率 | 有效范围 |
| --- | --- | --- | --- |
| 输入电压 | 2 字节 | 0.01 V/bit | 0 ~ 642.55 V |
| 输入电流 | 2 字节 | 0.05 A/bit | 0 ~ 3212.75 A |

自定义 PGN 的可选范围：

- **65280 ~ 65535**（0xFF00 ~ 0xFFFF）—— 行业保留
- **130816 ~ 131071**（0x1FF00 ~ 0x1FFFF）—— 制造商保留

上市产品还需向 SAE 申请**制造商编号**，它是每个节点 NAME 的一部分。

## 七、传输协议（TP）—— 多包传输

### 为什么需要

Classic CAN 数据帧只有 8 字节。当某个参数组需要 **9 ~ 1785 字节** 时，必须借助 J1939 的传输协议功能建立和关闭多包通信。

```text
1785 = 255 包 × 7 字节/包
```

### 两种传输模式对比

| 维度 | **BAM**（广播公告） | **CM**（连接模式） |
| --- | --- | --- |
| 连接方式 | 一对多 | 点对点 |
| 目标地址 | 全局 | 特定设备 |
| 流控 | 无，发送方全权负责 | 有，由接收方控制数据流 |
| 接收方能否干预 | **不能**（即使没收到包也无法示意） | 能（可随时终止） |
| 包间隔 | **50 ~ 200 ms** | **无时间限制**，各节点按最大速度 |
| 速度 | 较慢 | 更快 |
| 适用 | 整车配置同步、简单广播 | 固件下载、诊断大数据 |

### 报文拆装

- 数据域首字节定义为**数据包的序列编号**，从 **1** 开始依次分配。
- 每包（除最后一包）装载原始数据的 **7 字节**；最后一包不足部分用 **0xFF** 填充。

### 报文重组

接收方按序列编号顺序重组，还原为一条长字节串，再交给应用层模块处理。

### 连接管理消息（TP.CM，PGN 60416 / 0x00EC00）

| 控制字节 | 名称 | 发送方 | 说明 |
| --- | --- | --- | --- |
| 0x10 | CTS（清除发送） | 接收者 | 声明可接收的包数与起始包号 |
| 0x11 | EndOfMsgAck（消息结束应答） | 接收者 | 全部收齐，关闭连接 |
| 0x12 | RTS（请求发送） | 发送者 | 声明总长度、总包数、最大包数、目标 PGN |
| 0x13 | Conn_Abort（放弃连接） | 发送者或接收者 | 终止连接 |
| 0x14 | BAM（广播公告） | 发送者 | 广播长消息 |

### 数据传送消息（TP.DT，PGN 60160 / 0x00EB00）

仅由发送者发出。字节 0 为包号（1~255），字节 1~7 为数据。

### CM 点对点传输完整流程

以发送者 SA=0x55、接收者 SA=0x22、23 字节报文（拆成 4 包）为例：

```text
步骤 1  发送者 → TP.CM_RTS        声明 23 字节 / 4 包
步骤 2  接收者 → TP.CM_CTS        声明可接收从包号 1 开始的 2 个包
步骤 3  发送者 → TP.DT #1、#2      发送前 2 个包
步骤 4  接收者 → TP.CM_CTS        可再收 2 个包
                              （若暂时无法接收，最长延迟 500 ms 后须再发一条 CTS 保持连接）
步骤 5  发送者 → TP.DT #3、#4      发送后 2 个包
步骤 6  接收者 → TP.CM_EndOfMsgAck  全部收齐，关闭连接
```

**传输期间所有 TP 帧的 PGN 统一标识为 65259（0x00FEEB）** —— 注意这是 PDU2 广播格式下的 PGN 编码（PS = 组扩展 0xEB），与 TP.CM 字节 6~7 里携带的**被传输报文的目标 PGN（16 位截断形式）**是两回事，不要混淆：

| 位置 | 含义 | 值 |
| --- | --- | --- |
| TP 帧 CAN ID 中的 PGN | 标识"这是一组 TP 帧" | 65259（0x00FEEB） |
| TP.CM 字节 6~7 | 被传输报文的目标 PGN | 16 位（低字节在前） |

> 详细的 TP.CM 字节布局、CTS/Abort 语义、超时（T1~T4）与 C 代码骨架见 [[bus/automotive/j1939-transport-protocol|j1939-transport-protocol]]。

## 八、诊断：DTC 与 DM 报文

### DM 报文

SAE J1939 应用层定义了 **12 种诊断报文（DM）** 和诊断故障码（DTC）。DM 报文用于指示"故障灯"和"当前故障"。

| DM | 用途 |
| --- | --- |
| **DM1** | **当前故障**（Active DTC）+ 指示灯状态。**法规强制要求支持**，仪表故障灯由 DM1 控制 |
| DM2 | 历史故障（Previously Active DTC） |
| DM3 | 诊断数据 |
| DM11 | 诊断数据 |
| DM14 | 诊断信息 |
| DM15 | 诊断信息 |
| DM16 | 扩展诊断数据（内存/快照） |
| DM17 | 诊断数据 |
| DM18 | 诊断数据 |
| DM19 | 诊断数据 |
| DM20 | 诊断数据 |
| DM21 | 诊断数据 |

### DM1 报文结构

```text
字节 1     故障指示灯状态（点亮哪个灯需看字节 3 起的 DTC）
字节 2     指示灯闪烁方式（自检 / 闪烁类型）
字节 3     第一个 DTC 的 SPN 字节（LSB）
字节 4     第一个 DTC 的 SPN 中间字节
字节 5     第一个 DTC 的 SPN 高字节 + FMI 高 4 位
字节 6     FMI 低 4 位 + OC
字节 7-8   下一个 DTC（无则填 0xFF）
...
```

- DM1 的 PGN = **65226（0x00FECA）**。
- BCM 节点发出的 DM1，CAN ID = **0x18FECA21**。

### DTC 格式

J1939 的 DTC 格式**与 UDS 使用的 DTC 格式不同**：

| 字段 | 全称 | 取值 | 含义 |
| --- | --- | --- | --- |
| **SPN** | Suspect Parameter Number | 0 ~ 524287 | **故障发生的位置**（哪个参数/部件） |
| **FMI** | Failure Mode Indicator | 0 ~ 31 | 故障的**类型/性质**（超范围、短路、数据异常等） |
| **OC** | Occurrence Counter | 0 ~ 127 | 该故障的**发生次数** |
| **CM** | Conversion Method | 0 ~ 1 | 转换方法，通过定义 DTC 的字节排列来指定 |

DTC 的字节 1 默认为 0x44，字节 2 默认为 0xFF（部分格式版本）。

### 诊断系统设计流程

```text
1. 根据需求确定选用哪种 DM 报文
2. 结合发送节点确定 CAN ID（PGN + SA）
3. 设计 DTC 相关字段
```

> **关键**：每类诊断报文都有自己的 PGN，因此**可以直接从 CAN ID 判断该报文是不是诊断报文、是哪一种诊断报文**。

## 九、J1939 DA 与 DBC

### SAE 不维护 DBC

SAE **不维护也不定义** J1939 的任何 DBC 文件。SAE 维护和销售的是 **J1939 Digital Attachments（J1939-DA）**，一个 Excel 文件，承载"为 J1939 创建 DBC 所需的所有技术信息"。

```text
J1939-DA (Excel)
├── PGN 清单（含每个 PGN 的优先级、传输速率、SPN 列表）
├── SPN 清单（含位起始位置、位长度、分辨率、偏移、单位、范围）
└── 由各厂商据此生成自己的 DBC 文件
```

获取地址：<https://www.sae.org/search/?qt=j1939da>

### 规模

截至协议当前版本：

- 已标准化定义 **1500+ 个 PGN**
- 已标准化定义 **20000+ 个 SPN**

### 设计规则

- **可以**选用标准 PGN 中的**部分** SPN（不必全用），但**不允许改变 SPN 在该 PGN 中的字节排布**。
- PGN 值与报文 ID 密切相关：**由报文 ID 可算出 PGN**；**选定 PGN，ID 也就确定了**（再补上 SA 与优先级）。
- 若功能在 J1939 中无对应 PGN，可自定义报文（类似乘用车 CAN 通信矩阵设计），但须注意：
  - ID 的 **PF 字节必须为 0xFF**，表示自定义报文；
  - 信号长度**最少 2 bit**；
  - 枚举值中的最大值**必须为 Reserved**。

示例（摄像头遮蔽状态信号，2 bit）：

```text
0x0 = no block
0x1 = blocked
0x2 = Invalid
0x3 = Reserved   ← 枚举最大值必须保留
```

## 十、协议设计的工程意义

### 为什么商用车要标准化

商用车的特点：功能单一、生命周期长、产量小、利润不高。这要求在 E&E 架构设计时施加**约束**，以最大化软硬件复用、降低开发成本。

J1939 正是为此而生，它实现了两件事：

1. 按常见功能定义相关信号，**信号的长度、精度、偏移量全部标准化**。
2. 按功能需求把信号打包，对**报文类型、周期、ID 以及各信号在报文中的位置标准化**。

结果：设计者从协议中直接选标准报文组成通信矩阵即可；严格遵守 J1939 的不同工程师产出的设计结果**高度一致**，可读性强、出错概率低。

### 优点与代价

| 优点 | 代价 |
| --- | --- |
| 软硬件复用率高，节省开发成本 | PGN/SPN 更新速度跟不上商用车功能增长 |
| 不同厂商 ECU 可互通 | 通信内容易被破解（ID → PGN → 报文名 → 信号） |
| 设计文件可读性强，出错率低 | 部分场景需自定义 PGN，兼容性需额外约定 |
| 法规生态成熟（DM1 强制、OBD 合规） | 帧长固定 8 B、大数据必须走 TP |

> **实车改装价值**：若车辆严格遵守 J1939，理论上可轻易破解 CAN 网络拓扑及大多数报文 —— 通过 ID 即可知晓发送节点与 PGN，非自定义 PGN 均可通过协议查出报文名称与信号。即使没有整车 DBC，也能获取制动、转向、驱动等关键信号用于自动驾驶改装。主机厂通常会要求供应商严格遵守 J1939 以控制风险。

### J1939 vs CAN FD vs Ethernet 选型

| 场景 | 推荐 |
| --- | --- |
| 现有 J1939 网络 | 保持 J1939（经典 CAN） |
| 新设计，高速需求 | J1939 + CAN FD |
| 跨厂商（Tier 1）集成 | J1939（标准 PGN） |
| 域控制器（ADAS） | Ethernet（J1939 不够） |
| 整车主干网 | CAN FD + Ethernet |
| 卡车 / 客车 / 工程机械 | J1939 主流 |

## 十一、与 UDS / OBD-II 的关系

| 维度 | J1939 | UDS | OBD-II |
| --- | --- | --- | --- |
| 定位 | 商用车运行数据 + 诊断参数广播 | 完整诊断体系（会话、DID、例程、刷写） | 法规强制的**只读最小集** |
| 寻址 | PGN（29-bit ID 内嵌） | 物理寻址 / 功能寻址 | 功能寻址广播 0x7DF |
| 数据方向 | 周期广播为主 | 请求-响应 | 请求-响应 |
| 多帧 | 自带 BAM / TP | ISO-TP（ISO 15765-2） | ISO-TP（Mode 09 需扩展帧） |
| 会话/权限 | 无 | 有（种子密钥） | 无 |
| DTC 格式 | SPN + FMI + OC + CM | 3 字节 DTC | 3 字节 DTC |

> **OBD-II 与 UDS 是两套体系，不是升级关系**；同一辆车上两者共存，OBD-II 走 0x7DF 功能寻址，UDS 走 OEM 物理寻址。商用车另有 WWH-OBD（ISO 27145 系列）作为全球统一车载诊断，见 [[bus/automotive/wwh-obd|wwh-obd]]。

## 一句话总结

**J1939 = 三层协议族**：物理层（J1939-11/-14/-15/-17）+ 数据链路层（J1939-21/-22，含 TP 多包）+ 应用/诊断层（J1939-71/-73），外加网络管理（J1939-81）与网络层（J1939-31）；核心标识是 **PGN**（报文级，源自 29-bit ID）与 **SPN**（信号级 + 故障位置级），参数定义由 **SAE J1939-DA**（Excel，非 DBC）承载。
