# IEC 101 产线死机案例库

## 目标

把产线常见的 IEC 101 串行通信失败、RS485 接线错、控制域解析错、FCB 状态机错、CS 校验错等写成案例库。

## 案例 1：RS485 A/B 反接

### 现象

主站和 RTU 都加电，串口参数正确，但完全不通信。

### 排查

```text
用万用表测 A/B 差分电压：约 200mV（应该 2-5V）
原因：A/B 反接
```

### 修复

交换 A/B 线序。

### 复盘

```text
1. RS485 不同厂商命名不同（A/B vs +/-, T/R vs A/B）
2. 不通信时优先交换 A/B 验证
3. 用示波器看差分电压判断
4. 调试工具：USB-RS485 + 串口助手
```

## 案例 2：DE 等待 TXE 但截断最后字节

### 现象

主站发命令 RTU 不响应，但 RTU 看主站帧最后 1 字节错（乱码）。

### 抓包

```text
主站 → RTU（逻辑分析仪）：
  TXE → DE = 0 关闭   # 错误：等 TXE 就关
  最后 1 字节只有 bit 0-2，后 5 bit 丢失
```

### 定位

主站 DE 等待 TXE 而不是 TC。TXE 是数据寄存器空，TC 才是移位寄存器空。

### 修复

```c
/* 等 TC 而不是 TXE */
while (!UART_TC_FLAG);   // TC 置位
RS485_DE = 0;
```

### 复盘

```text
1. RS485 半双工 DE 必须等 TC
2. TXE 在 9600 baud 下可能截断 1-2 bit
3. 工程实践：DE 高 → 发送 → 等 TC → DE 低 → 接收
4. 同样问题在 Modbus RTU 常见
```

## 案例 3：终端电阻过多

### 现象

主站 + 单 RTU 通信正常；多挂 RTU 后通信异常。

### 排查

```text
每个节点都加了 120Ω 终端
3 个节点 × 120Ω 并联 = 60Ω（负载过重）
```

### 修复

只在总线**两端**各加 120Ω 终端。

### 复盘

```text
1. RS485 终端电阻只在两端加
2. 中间节点不能加
3. 多节点通信失败先看终端
4. 用示波器看波形反射判断
```

## 案例 4：控制域 PRM 位解析错

### 现象

主站发复位命令，RTU 识别为响应命令，回复混乱。

### 抓包

```text
主站 → RTU：10 40 01 00 41 16    # PRM=1 (主站)
RTU 解析：0x40 = DIR=1, PRM=0 (从站)  # 错
```

### 定位

RTU 端 PRM 位掩码错误（按从站协议解析）。

### 修复

```c
/* 主站启动控制域解析 */
uint8_t dir = (control & 0x80) >> 7;   // 0 = 主站启动
uint8_t prm = (control & 0x40) >> 6;   // 1 = 主站启动
```

### 复盘

```text
1. PRM 位是协议层语义，不能简单按 DIR 解析
2. 不同协议（IEC 101 vs DNP3 vs Modbus）控制域不同
3. 必须按位协议定义逐位解析
```

## 案例 5：FCB 翻转不同步

### 现象

主站发命令 RTU 偶发不响应。

### 抓包

```text
主站：10 49 01 00 4A 16  # 请求链路状态 FCB=0
RTU：10 8B 01 00 8C 16  # 链路状态 OK（未复制 FCB）
主站：10 49 01 00 4A 16  # 请求链路状态 FCB=1
RTU：丢弃（FCB 不匹配）
```

### 定位

RTU 未复制主站 FCB 翻转。

### 修复

```c
/* RTU 端 */
if (fcv == 1) {
    if (fcb != last_fcb) {
        // FCB 翻转，处理
        last_fcb = fcb;
    } else {
        // FCB 未翻转，丢弃
        return;
    }
}
```

### 复盘

```text
1. IEC 101 FCB 状态机必须 RTU + 主站同步
2. RTU 收到 FCV=1 时帧开始 frame 翻转
3. RTU 响应必须复制主站 FCB
4. 测试用例必须覆盖 FCB 翻转边界
```

## 案例 6：CS 校验错

### 现象

主站发命令 RTU 不响应。RTU 解析 CS 错。

### 抓包

```text
主站：10 40 01 00 41 16
RTU 计算 CS = 0x40 + 0x01 + 0x00 = 0x41（正确）
RTU 计算 CS = 0x68 + 0xAA + ... + ... + 0x16    # 错（包含了 0x68）
```

### 定位

RTU 端 CS 计算范围错（包含了启动字符 0x68）。

### 修复

```c
/* RTU 端 CS 计算（正确） */
uint8_t cs = 0;
for (i = 1; i < len - 2; i++) {    // 跳过启动字符 0x68 和结束 0x16
    cs += buf[i];
}
```

### 复盘

```text
1. IEC 101 CS 计算范围 = 控制域 + 链路地址 + ASDU 长度 / ASDU
2. 启动字符 0x68 不计入 CS
3. 结束字符 0x16 不计入 CS
5. 不同实现略有差异，必须按协议规范
```

## 案例 7：ASDU 长度字段错

### 现象

主站发可变长度帧，RTU 接收但解析数据错。

### 抓包

```text
主站：68 0C 0C 68 73 01 64 01 06 00 01 00 01 00 00 00 7D 16
RTU 解析：LEN = 0x0C = 12
但实际数据只有 11 字节
```

### 定位

主站 LEN 字段包含了启动字符。

### 修复

LEN = 控制域 + 地址 + ASDU 字节数（不含启动字符）。

### 复盘

```text
1. IEC 101 LEN 字段表示剩余字节数（不含 0x68 + LEN 自身）
2. 计算要按规范
3. 测试用例必须覆盖多帧长度
```

## 案例 8：串行链路半双工冲突

### 现象

主站发命令，RTU 同时响应，总线冲突。

### 抓包

```text
主站：10 49 01 00 4A 16    # 请求链路状态
RTU：10 8B 01 00 8C 16    # 响应（同一时刻）
总线：乱码
```

### 定位

RTU 端自动响应未等待主站发送完。

### 修复

```c
/* RTU 端 */
while (RS485_RE) {
    // 等待主站发送完（DE/RE 翻转）
    wait_for_silence();
    process_request();
}
```

### 复盘

```text
1. 半双工 RS485 必须错开收发时序
2. RTU 不能在主站发送中响应
3. 工程实践：等待 3.5 字符时间静默
```

## 案例 9：FT1.2 固定 / 可变帧识别错

### 现象

主站发可变长度帧，RTU 解析为固定长度帧。

### 抓包

```text
主站：68 0C 0C 68 73 01 ...
RTU 解析：固定帧（0x10 0x01）模式
```

### 定位

RTU 端帧定界识别错。

### 修复

```c
/* RTU 端帧定界 */
if (buf[0] == 0x10 && buf[1] == 0x01) {
    // 固定长度帧
} else if (buf[0] == 0x68) {
    // 可变长度帧
}
```

### 复盘

```text
1. IEC 101 帧定界有两种格式
2. RTU 实现必须分别处理
3. 固定长度帧 = 11 字节
4. 可变长度帧 = 6 + LEN + ASDU 字节
```

## 案例 10：偶校验错

### 现象

主站和 RTU 串口参数都是 8N1，但实际表都是 8E1。

### 排查

```text
抓字节：字节错位
原因：偶校验位错（主站 RTU 一致 8E1 但上位机用 8N1）
```

### 修复

确认主站 / RTU / 上位机串口参数完全一致（8E1）。

### 复盘

```text
1. IEC 101 通常 8E1（数据+偶）
2. 多设备网络必须参数一致
3. 调试工具与设备参数一致
```

## 案例 11：IOA 字节数 2 vs 3

### 现象

主站发 3 字节 IOA，RTU 只支持 2 字节。

### 抓包

```text
主站：68 ... 00 01 00 64 01 ...    # IOA = 00 01 00（3 字节）
RTU 解析：IOA = 00 01    # 截断 3 字节 → 2 字节
```

### 定位

RTU IOA 字节数配置错。

### 修复

修改 RTU IOA 字节数 = 3。

### 复盘

```text
1. IEC 101 IOA 早期 2 字节，扩展 3 字节
2. 工程实践：101/104 兼容 3 字节
3. 部署前必须确认 RTU 配置
```

## 案例 12：GI 通用分类不识别

### 现象

RTU 上报 GI 数据（ASDU 240-249），主站不识别。

### 定位

主站不支持 GI。

### 修复

主站补 GI 解析。

### 复盘

```text

```

## 案例 13：命令选择超时未执行

### 现象

主站发选择命令 RTU 响应，但主站未发执行。RTU 选择超时后报"命令超时"。

### 修复

主站选择命令后立即发执行（同一会话内）。

### 复盘

```text
1. IEC 101 命令选择超时通常 30s-2min
2. 主站必须立即发执行
3. 工程实践：选择 + 执行间隔 < 5s
```

## 案例 14：时钟同步后变位时间错

### 现象

主站发 C_CS_NA_1 时钟同步后，RTU 变位时间错。

### 抓包

```text
主站：C_CS_NA_1 CP56 = 24 10 25 12 08 30
RTU → M_SP_TB_1 CP56 = 24 10 25 13 08 30    # 1 小时后
```

### 定位

时区处理（与 IEC 104 案例 14 类似）。

### 修复

主站 / RTU 约定时区处理。

### 复盘

```text
1. IEC 101 时钟同步时区处理与 IEC 104 一致
2. 国内 RTU 按本地时间（UTC+8），主站适配
3. CP56 不带时区字段
```

## 案例 15：突发上传堆积

### 现象

突发模式启用后，主站接收数据堆积，帧丢失。

### 修复

主站 S 帧加速，RTU 突发合并。

### 复盘

```text
1. IEC 101 突发上传与 IEC 104 类似
2. 串行链路更慢，更容易堆积
3. 工程实践：突发合并 + 优先级
```

## 案例 16：双点命令 SE 选择错

### 现象

主站发 C_DC_NA_1 SE=1（选择），但 RTU 当作 SE=0（执行）执行。

### 抓包

```text
主站：68 ... C_DC_NA_1 SE=1    # 选择
RTU：执行开关动作    # 错（应该等 SE=0）
```

### 定位

RTU 端 SE 选择处理逻辑错。

### 修复

```c
/* RTU 端 */
if (se == 1) {
    // 选择阶段，不动作
    cache_command();
} else {
    // 执行阶段
    execute_command();
}
```

### 复盘

```text
1. 双点命令必须 SE=0 才执行
2. 选择阶段不动作（防误操作）
3. RTU 端命令处理必须严格区分 SE
```

## 案例 18：主站请求响应错位

### 现象

主站发请求 1，RTU 响应请求 2 的内容（错位）。

### 抓包

```text
主站：1. 请求链路状态
主站：2. 请求链路状态（未等响应）
RTU：响应请求 2 内容（但主站以为响应请求 1）
```

### 定位

主站并发请求未按顺序匹配。

### 修复

主站发请求必须等响应。

### 复盘

```text
1. IEC 101 是主从协议，必须一问一答
2. 不能并发请求
3. 收到响应必须匹配对应请求
```

### 修复

主站 IOA 偏移调整或 RTU 配置调整。

### 复盘

```text
1. IEC 101 IOA 偏移（0 vs 1）必须主站 / RTU 约定
2. 测试用例必须验证 IOA 偏移
```

## 案例 20：复位后 FCB 不同步

### 现象

主站发 F1 链路维持，FCB 状态混乱。

### 抓包

```text
主站：复位命令
主站：发请求 FCB=1
RTU：FCB 状态未初始化
```

### 定位

RTU 端复位命令未重置 FCB 状态。

### 修复

```c
/* RTU 端 */
void on_reset_link() {
    last_fcb = 0;
    fcv_valid = 0;
}
```

### 复盘

```text
1. 复位命令必须重置 FCB 状态
2. 测试用例必须覆盖复位路径
```
